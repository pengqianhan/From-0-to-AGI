## 检验问题（按难度递进）

**第一关：概念——生成循环与解码策略**

问用户：
> 用几句话描述语言模型"生成一段话"的循环。然后说说：温度 T、top-k、top-p 分别在循环的哪一步起作用？T → 0 时会退化成什么？

期望回答：循环是"喂入当前序列 → 取最后一个位置的 logits → 按策略挑一个 token → 接到序列末尾 → 重复"（自回归）。三个旋钮都作用在"挑一个 token"这一步：温度是 logits 除以 T 再 softmax（T 小更尖、T 大更平）；top-k 只保留概率最大的 k 个；top-p 按概率从大到小累加，凑够 p 就截断，然后重新归一化再抽样。T → 0 退化成贪心（argmax）。

---

**第二关：直觉——为什么 top-p 比 top-k 更"聪明"**

问用户：
> 本章代码里，"What is th" 后面 top-p=0.9 只留下 5 个字符，而一段台词刚开头时留下 15 个。top-k=5 在这两种情况下分别会出什么问题？

期望回答：模型很确定时（下一个几乎一定是 e），固定留 5 个可能把一些本该砍掉的离谱候选也留下；模型不确定时（很多字都合理），只留 5 个又把合理的候选砍掉了，生成会变单调。top-p 留下的个数随分布的"把握程度"自动伸缩（Holtzman 等 2019 的 nucleus sampling 的核心论点）。加分：实践中常常两者一起用（如 Qwen3 默认 top-k 20 + top-p 0.95）。

---

**第三关：发现问题——KV cache 省了什么、没省什么**

问用户：
> 不用 KV cache 生成 n 个 token，总共要处理大约多少个位置？用了之后呢？为什么缓存 K 和 V，却不缓存 Q？另外，KV cache 把什么问题换成了什么新问题？

期望回答：朴素版第 t 步要把整段（提示词 + 已生成的 t 个）重算一遍，总共约 n²/2 个位置（本章实测生成 512 个字：137,984 vs 525）；缓存版每步只算新 token 自己的 q/k/v，总共约 n 个。因果注意力下过去位置的 K、V 不会因为新 token 而改变，所以可以复用；Q 只在"当前 token 去看历史"时用一次，以后不会再用。代价是显存：`2 × 层数 × KV 头数 × head_dim × 序列长度 × 字节数`，主线模型每 token 112 KiB，32K 上下文 3.5 GiB，是权重的 2.7 倍——计算瓶颈变成了显存瓶颈。加分：能说出 prefill（并行、算得满）与 decode（一次一个 token、算得不满）的区别。

---

**第四关：迁移——算一笔 GQA 的账**

问用户：
> 一个模型 32 层、32 个查询头、head_dim 128，BF16。分别按 MHA、8 个 KV 头的 GQA、MQA，算 8K 上下文下一条序列的 KV cache。GQA 里 8 个 KV 头意味着每几个查询头共享一组 K/V？为什么不是所有模型都直接用最省的 MQA？

期望回答：每 token = 2 × 32 × KV头 × 128 × 2 字节。MHA（32 个 KV 头）每 token 512 KiB，8K 上下文 4 GiB；GQA（8 个）每 token 128 KiB，8K 上下文 1 GiB；MQA（1 个）每 token 16 KiB，8K 上下文 128 MiB。GQA-8 是每 4 个查询头共享一组。MQA 只剩一组 K/V，表达能力损失更大、训练可能更不稳定；GQA 论文的结论是分组共享的质量接近 MHA、速度接近 MQA，所以主流模型（Llama 3、Qwen3、Mistral 等）多选 GQA 的折中点。加分：知道第 21 章的 MLA 用低秩压缩走了另一条路；以及本章小实验里 MHA/GQA/MQA 的 loss 差别要和"换个随机种子"的差别比较后才能下结论。

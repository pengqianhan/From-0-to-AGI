## 二、分镜与旁白

### S01 片头
- 画面：章节标题卡淡入："第 17 章 / 蒸馏 / From 0 to AGI"，副标题"让小模型向大模型学"。
- 屏幕文字：第 17 章 · 蒸馏
- 旁白：上一章我们用 SFT 教会了模型按格式对话、调用工具。但 SFT 的标准回答从哪来？人工写太贵，小模型自己写又不够好。这一章的答案是：找一个更强的模型当老师，这就是蒸馏。我们会讲三种蒸馏、一道筛数据的关卡，再加一张教师许可证的表。

### S02 大家都这么做
- 画面：左边一个大方块"教师"，右边小方块"学生"，箭头相连；右侧四行采用方逐条出现。
- 屏幕文字：Llama 3.2 · Gemma 2/3 · Qwen3 小模型 · DeepSeek-R1-Distill
- 旁白：今天的小模型几乎都是蒸馏出来的。Llama 3.2 的一 B 和三 B，用 8B 和 70B 的 logits 当训练目标。Gemma 2 的小模型用蒸馏代替了普通的预训练目标。千问三的小模型不走旗舰的完整流程，改用强到弱蒸馏，算力只要十分之一。DeepSeek 用 R1 生成的八十万条数据，直接微调出一批小模型。

### S03 one-hot 与软标签
- 画面：上文"今天天气很 __"；左边柱状图 one-hot（只有"好"是 1），右边柱状图教师分布（好 0.607、热 0.223……）。
- 屏幕文字：one-hot：0 bit　　教师软标签：1.535 bit
- 旁白：普通训练的标签是 one-hot：训练文本里下一个字是"好"，就只告诉模型"好"。可是"热""冷""晴"也说得通，"猫""跑"绝对不行。教师给出的是一整张分布，它不光说答案是什么，还说哪些次优、哪些荒唐。这些藏在错误答案里的信息，常被叫作暗知识。

### S04 温度
- 画面：教师柱状图随温度 {τ|tau} 从 0.5 变到 4 逐渐变平，右侧显示熵和 p(晴)/p(猫) 的比值。
- 屏幕文字：p_T^τ = softmax(z_T / τ)
- 旁白：教师往往很自信，"猫"的概率只有千分之二，学生几乎看不见。办法是加温度：logits 先除以 {τ|tau} 再做 softmax。{τ|tau} 越大，分布越平，排在后面的候选分到越多概率。温度从一升到四，晴和猫的概率之比从四十五倍缩到两点六倍，但排名始终不变。训练时学生也用同一个温度。

### S05 KD 损失与梯度
- 画面：公式 L = τ²·KL(p_T‖p_S) 写出；下方两组柱状图对比硬标签梯度 p_S − onehot 和 KD 梯度 τ·(p_S − p_T)。
- 屏幕文字：∂L/∂z_S = τ·(p_S^τ − p_T^τ)
- 旁白：蒸馏的损失是教师分布和学生分布之间的 KL 散度，再乘上 {τ²|tau 的平方}。求一下梯度，得到 {τ|tau} 乘以学生分布减教师分布。这和第五章的"预测减去 one-hot"是同一个形状，只是目标换成了教师的分布。看柱子：硬标签只把"好"往上推，其余一律往下压；蒸馏会发现学生低估了"热"和"晴"，也把它们往上推。乘 {τ²|tau 的平方}，是为了换温度时梯度大小不变。

### S06 同一个词表
- 画面："今天天气很好"被两种词表切成 4 个和 3 个 token，位置对不上画红叉；下方表格：65,536 → 689.5M；151,936 → 800.1M（+110.6M）。
- 屏幕文字：logits 蒸馏要求同一个分词器
- 旁白：logits 蒸馏有个硬条件：教师和学生必须用同一个分词器。同一句话，两个词表切出来的 token 个数和边界都不一样，第几个位置、第几维，都对不上。我们的主线模型用第十三章自己训的六万五千词表，和任何开源教师都不同，所以只能走另一条路。如果换成千问的词表，embedding 要多一亿一千万参数，总量刚好超过零点八 B 的上限。

### S07 序列级蒸馏与玩具实验
- 画面：教师"写"一段文字，学生照着学；然后横向柱状图显示五组验证 bits/char：A 3.679、B 3.362、C 3.290、D 3.344、R 3.143。
- 屏幕文字：玩具实验：字符级 MLP，学生只看 2 万字符
- 旁白：另一条路叫序列级蒸馏：让教师把回答写出来，学生在上面做普通的 SFT。对教师只要求能生成文本，什么分词器都行，DeepSeek 的蒸馏模型就是这样做的。我们做了个玩具实验：学生只能看两万个字符。用硬标签，验证集三点六八，明显过拟合；学教师写的文字，三点三六；在同样的两万字符上学教师的整张分布，三点二九，最好。数据少的时候，软标签的好处最大。

### S08 前向 KL 与反向 KL
- 画面：双峰的教师曲线（灰）；先画前向 KL 的解（宽高斯，盖住两峰，山谷里有很多概率）；再画两条反向 KL 的解（窄高斯，各自落在一个峰上）。
- 屏幕文字：前向 KL：覆盖所有可能　　反向 KL：挑一个模式
- 旁白：KL 散度有两个方向。上面两种蒸馏都在最小化前向 KL：教师有概率的地方，学生都得覆盖。当学生只能画一个峰，它就摊开来盖住两个峰，结果在两峰之间的山谷里放了百分之二十四的概率，教师在那里只有百分之一点六。反过来最小化反向 KL，学生会缩进一个峰里，把另一个整个放弃，落到哪个峰取决于起点。

### S09 在线策略蒸馏
- 画面：学生写出一串 token，教师在每个 token 上打分（颜色越深扣分越多）；右侧对比表：RL 17,920 GPU 时 / AIME 67.6，在线策略蒸馏 1,800 GPU 时 / AIME 74.4。
- 屏幕文字：学生采样 + 教师逐 token 打分 = 在线策略蒸馏
- 旁白：反向 KL 要在学生自己的分布上算，于是就有了在线策略蒸馏：学生自己写回答，教师在每一个 token 上打分。学生在自己真正会犯错的地方得到纠正，而且是逐 token 的稠密信号，不像强化学习一整段只有一个分数。千问三的实验里，它用十分之一的 GPU 时，成绩超过了直接做强化学习。千问、Gemma、GLM、小米 MiMo、DeepSeek V4 都在用它。可惜它也要求同一个词表，主线模型用不上。

### S10 拒绝采样的漏斗
- 画面：漏斗逐层变窄：候选 1600 → 格式正确 1303 → 调用正确 768 → 执行 + 回答正确 669 → 每任务留 1 条：193。
- 屏幕文字：多采样，只留执行验证通过的
- 旁白：教师也会犯错：参数写错、选错工具、JSON 写坏。所以每个问题让教师多采几次，只留能验证正确的，这叫拒绝采样。工具调用最适合这么做，执行一下就知道对不对。我们用一个会犯错的模拟教师演示：一千六百个候选，格式对的一千三百，调用对的七百六十八，真正执行并答对的六百六十九，每个任务留一条，剩一百九十三条。宁可少，不可错。

### S11 验证器的漏洞（极小配置演示）
- 画面：右上角"极小配置演示"标注；冒烟测试的数字：96 个候选 → 1 条通过；那一条对话被放大："讲一句鼓励的话。" → "坚下云，气温 28°C。"；下方 loss 0.269 = 0.5·ce 0.526 + 0.5·kd 0.0116。
- 屏幕文字：验证器只保证它检查的东西
- 旁白：但验证器只保证它检查的东西。冒烟测试里，一个极小模型当替身教师，九十六个候选只通过一条。偏偏就是这一条：用户说"讲一句鼓励的话"，助手答"坚下云，气温二十八度"。不需要工具的任务只检查有没有乱调工具，不检查内容，胡话就混了进来。第二步之前，必须给这类任务补上内容判分。

### S12 教师的许可证
- 画面：许可证表格逐行出现：Qwen3/Qwen3.5 Apache-2.0 ✓；DeepSeek-R1/V4、GLM-5、MiMo MIT ✓；gpt-oss Apache-2.0 ✓；Gemma 1–3 ✗（Model Derivatives）；Llama ✗（名字须以 Llama 开头）。
- 屏幕文字：教师许可证：只用 Apache-2.0 / MIT
- 旁白：最后一件事：老师不是想用就能用。蒸馏数据会跟着我们的模型一起发布，许可证的条款会传到学生身上。千问和 gpt-oss 是 Apache 2.0，DeepSeek、GLM、MiMo 是 MIT，都可以。Gemma 一到三代规定，用它的输出训练出来的模型也算它的衍生品；Llama 要求这样的模型名字以 Llama 开头。主线只用 Apache 和 MIT 的教师，并把教师的名字、版本、许可证写进每一条数据。

### S13 小结
- 画面：四个方块"软标签 → 同一词表？→ 序列级 / logits / 在线策略 → 验证 + 许可证"；最后出现"下一章：偏好对齐"。
- 屏幕文字：软标签 · 温度 · 同一个词表 · 验证 · 许可证
- 旁白：回顾一下：软标签比 one-hot 多带信息，温度把它放大；logits 蒸馏和在线策略蒸馏信息最多，但要同一个词表；序列级蒸馏只要教师能写字，是我们主线要走的路；数据要多采样、靠执行验证筛过；老师的许可证要读原文。蒸馏只教模型"怎么答"，下一章，我们教它分辨哪个回答更好。

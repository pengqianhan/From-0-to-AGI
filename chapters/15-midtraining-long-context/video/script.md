## 二、分镜与旁白

### S01 片头
- 画面：章节标题卡淡入："第 15 章 / 中期训练与长上下文"，副标题"最后一段怎么训，读不长怎么办"。
- 屏幕文字：第 15 章 · 中期训练与长上下文
- 旁白：上一章，主线模型的预训练已经跑在稳定段上了。这一章处理预训练收尾的两件事：学习率降下来的最后一段该怎么训，以及一个只读过四千个 token 的模型，怎么学会读三万两千个 token。

### S02 两个问题
- 画面：一条时间线：灰色"预训练（稳定段）"、橙色"中期训练"、紫色"长上下文"，右边"Base 模型 → 闸门 2"。下方两个问题依次出现，连线指向对应的段。
- 屏幕文字：问题一：学习率最低的那一段，喂什么数据？问题二：只见过 4K 的模型，怎么读 32K？
- 旁白：把预训练的尾巴拆开看，是这样一条时间线。最长的是稳定段，学习率不变，用四千长度的片段。之后是中期训练，学习率降到零。最后是长上下文扩展。第一个问题：学习率最低的那一段，应该喂什么数据？第二个问题：只见过四千长度的模型，怎么读三万两千？两件事做完，主线的 Base 模型就出炉了，接着要过闸门二。

### S03 衰减段换数据
- 画面：左边 WSD 学习率曲线，衰减段标橙色并加一条"5–10% 的算力"色带；右边两条配比色块："稳定段的配比"（网页为主）→"衰减段的配比"（高质量网页、数学、代码、指令）。底部列出采用方。
- 屏幕文字：OLMo 2 · Llama 3 · SmolLM3 · MiniCPM · Qwen3 · MobileLLM-R1
- 旁白：第六章讲过 WSD 学习率：先热身，再长时间保持不变，最后一小段降下来。几乎所有头部开源模型，都在降下来的这一段换数据：少一些普通网页，多一些高质量网页、数学、代码和指令式的数据。这一段叫退火，也叫中期训练，只占百分之五到十的算力。OLMo 2、Llama 3、SmolLM3、MiniCPM、Qwen3 和 MobileLLM-R1 的报告里都写明了这样做。

### S04 为什么放在衰减段
- 画面：三条理由依次出现；下方 OLMo 2 7B 的对比条：10 项平均 53.0 → 62.9，GSM8K 24.1 → 67.5。
- 屏幕文字：① 学习率降下来，参数落进谷底 ② 好数据少，集中用 ③ 分叉衰减，便宜地比较数据
- 旁白：为什么要放在这一段？第一，学习率降下来，参数才会落进谷底，这一段决定了模型最后停在哪。第二，高质量的数学和代码数据很少，摊在几万亿 token 里就淹没了，不如集中用在最有分量的这一段。第三，想比较两份数据，只要从同一个检查点分出两小段衰减就行，不用从头训练。效果很直观：OLMo 2 七 B 每一遍中期训练只有五百亿 token，十项评测平均从五十三分涨到六十三分，GSM8K 从二十四分涨到六十七分。

### S05 小实验：衰减 × 换数据
- 画面：右上角"极小配置演示"。左边一条主干分出四条支路（A 恒定+原配比、B 衰减+原配比、C 恒定+新配比、D 衰减+新配比）；右边四根横条是代码验证集的 bits/字节，D 被框出。
- 屏幕文字：代码验证集 bits/字节（越低越好）
- 旁白：我们在 CPU 上做了个极小的版本。一个字节级的小模型，数据有英文、中文和代码三种，代码只占一成，好比真实模型里想补强的数学。主干以恒定学习率训练八百步，然后从同一个点分出四条支路，各训两百步：学习率降不降，配比换不换，把代码提到五成。看代码验证集的 bits per byte：只衰减，从二点六四降到二点四七；只换数据，降到二点一九；两者一起，降到二点零九，最好。代价是英文和中文比只衰减的那条差一点，真实的中期训练也要做这样的取舍。

### S06 为什么读不长
- 画面：三块钟表（第 24、48、63 对，θ = 1 万），指针随"位置"计数从 0 转到 4096，扫过的弧标绿；再从 4096 转到 32768，超出绿弧的部分标红。
- 屏幕文字：绿色：训练时见过的角度 红色：读到 32K 时才转到的角度
- 旁白：再看第二个问题。第九章讲过，旋转位置编码 {RoPE|肉普} 把向量的维度两两配对，每一对像一根转速不同的指针，位置每前进一个 token，指针转一个固定角度。快的指针在四千个 token 里转了几十圈，所有角度都见过。慢的指针连一圈都转不满，训练时只见过绿色这一小段弧。等到读三万两千个 token，它们会转进红色这段从没见过的角度，模型就不认识了。另外，候选位置多了八倍，注意力也会被摊薄。

### S07 波长表
- 画面：公式 λ_i = 2π·θ^(2i/d)；一张波长表（第 0、16、32、48、63 对 × θ = 1 万、50 万、100 万），超过 4096 的标红；右边两行统计。
- 屏幕文字：4K 内转不满一圈：θ=1 万 18 对，θ=100 万 33 对；读到 32K 遇到没见过的角度：不改 18 对，调到 100 万 0 对
- 旁白：指针转一圈需要的 token 数，叫波长，等于二派乘以基频 {θ|西塔} 的二 i 除以 d 次方。主线模型每个头有六十四对指针。基频是一万时，有十八对在四千个 token 内转不满一圈，读到三万两千就会遇到没见过的角度。把基频调到一百万，转不满一圈的反而变多了，可读到三万两千时，没见过的角度一个都没有了。为什么？下一镜看。

### S08 调大基频
- 画面：公式 θ: 10⁴ → 10⁶；五根竖条表示第 0、16、32、48、63 对各变慢多少倍（1.0、3.2、10.0、31.6、93.1）；底部列出采用方。
- 屏幕文字：Qwen3：长上下文阶段 1 万 → 100 万 · SmolLM3：150 万 → 500 万 · Llama 3：50 万
- 旁白：基频调大，所有指针一起变慢，但慢的程度不一样。最快的那一对几乎不变，所以近处的位置照样分得清。越慢的指针被放慢得越多，最慢的那一对慢了九十多倍，读到三万两千也还在见过的范围里。代价是同一个角度对应的距离变了，所以要在新基频下接着训练一段。Qwen3 在长上下文阶段把基频从一万调到一百万，SmolLM3 调到五百万，Llama 3 从一开始就用五十万。

### S09 位置内插 PI
- 画面：公式 ω_i → ω_i/s；两个圆：左边"原来"，位置 0–4 在最快那一对上相隔 1 弧度；右边"PI ×8"，五个点挤在一起，只差 0.125 弧度。
- 屏幕文字：不越界了，但近处的位置挤在一起、难以分辨
- 旁白：另一个思路叫位置内插，简称 PI：要扩八倍，就把所有指针都放慢八倍，相当于把位置压扁。这样确实不会越界了，可是最快的那根指针也被放慢了。原来相邻两个 token 差一弧度，现在只差零点一二五弧度，近处的位置挤在一起，模型很难分清谁先谁后。

### S10 YaRN
- 画面：16 根竖条表示本章小实验里每个维度对"保留原频率的比例"（绿：保留，橙：过渡，紫：完全内插）；右侧图例和温度公式 √(1/t) = 0.1·ln s + 1，s = 4 时 1.139。
- 屏幕文字：转了 ≥32 圈：原样保留；中间：线性过渡；不满 1 圈：÷ s
- 旁白：{YaRN|亚恩} 把两种想法合在一起：只压慢指针，不碰快指针。它先数一数每根指针在训练长度里转了几圈：转了三十二圈以上的，原样保留；连一圈都没转满的，放慢 s 倍，和 PI 一样；中间的线性过渡。另外再乘一个温度，零点一乘 {ln s|l n s} 加一，让注意力重新变尖，补偿候选变多带来的摊薄。扩四倍时，这个数是一点一四。

### S11 从零实现与对拍
- 画面：四行核心代码逐行出现；下方"本章 02 脚本 = zero.model = transformers（Qwen3）"，以及最大差。
- 屏幕文字：频率最大差（float32 舍入），温度完全相同
- 旁白：写成代码只有十几行：一个斜坡算出每对保留多少，新频率是原频率和除以 s 的频率按比例混合，再算出温度。我们把它和主线代码 zero，还有 transformers 官方的实现放在一起比，频率只差浮点舍入，温度完全相同。

### S12 小实验：loss vs 长度
- 画面：右上角"极小配置演示"。左图"不训练，直接换 RoPE"：四条折线（不改、PI、YaRN、调大基频）在长度 64/128/256 上的验证 loss；右图"再用长度 256 微调 150 步"。
- 屏幕文字：只用长度 64 训练，读 128、256
- 旁白：再做一个极小实验。第九章的小模型，只用长度六十四的片段训练，然后读一百二十八和二百五十六。左图是不做任何训练、只换位置编码的结果。什么都不改，越过六十四以后 loss 就往上走，读到二百五十六时涨到将近一点九。PI 最糟，连六十四以内都变差了，因为快指针也被压慢了。只调大基频几乎没有帮助，它本来就要配合续训。YaRN 的线几乎是平的，只在短文本上付出一点代价。右图是再用长度二百五十六微调一百五十步之后：差距大幅缩小，YaRN 仍然最低，但和不改、调大基频只差零点零一左右，单个种子分不出高下；PI 仍然落后。

### S13 代价与数据
- 画面：两根堆叠条：4K 每 token 6.96 GFLOP（注意力 41%），32K 26.69 GFLOP（84%）；下面四条要点依次出现。
- 屏幕文字：只在最后训一小段；数据要真的长；合成长任务；标准：短文本恢复 + 大海捞针全对
- 旁白：长上下文为什么只在最后训一小段？因为贵。主线模型用四千长度训练，每个 token 大约七十亿次运算；换成三万两千长度，涨到二百六十七亿次，注意力占了八成多。所以 Llama 3 用大约八千亿 token、分六段扩到十二万八千。数据也要真的长：Qwen3 的长文本里，四分之三在一万六到三万二之间，另外留四分之一较短的，防止短文本能力退化。Llama 3 判断每一段扩展成不成功有两条标准：短文本评测完全恢复，大海捞针全部答对。

### S14 怎么评
- 画面：右上角"极小配置演示"。左边 tiny 模型大海捞针的"长度 × 深度"准确率表；右边 RULER 的要点。
- 屏幕文字：RULER：4 类 13 个任务；NIAH 几乎满分，RULER 随长度明显下降
- 旁白：大海捞针，就是在一大段无关文字的某个位置藏一句话，比如某某的密码是一串数字，最后问模型密码是多少。我们给主线代码写了这个工具，先拿一百三十万参数的小模型试了试，每一格都是零，这很正常，也如实报告。但要注意，大海捞针只是冒烟测试。英伟达的 {RULER|如勒} 基准有四类十三个任务，他们测了十七个模型，大海捞针几乎都是满分，换成更难的任务就随长度明显下降，声称支持三万两千以上的模型，只有一半在三万两千时还达标。

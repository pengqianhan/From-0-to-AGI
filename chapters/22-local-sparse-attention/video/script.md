## 二、分镜与旁白

### S01 片头
- 画面：标题卡"第 22 章 / 局部与稀疏注意力"淡入，副标题"只看附近，也不丢掉远处"。
- 屏幕文字：第 22 章 · 局部与稀疏注意力
- 旁白：上一章我们给 KV cache 记了账：上下文越长，要存的越多，要算的也越多。这一章换个思路：每个 token 真的需要看全部历史吗？如果只看附近一段，会省下什么，又会丢掉什么？我们会从最简单的滑动窗口讲起，看它省了多少，又在哪里失效，再看真实模型怎么把局部和全局搭配起来，最后看稀疏注意力。

### S02 全注意力的两笔账
- 画面：一个 16×16 的注意力矩阵，下三角逐行填满（紫色），旁边计数器显示"要算的对数"按平方增长；右边一根 KV cache 柱子随行数变长。
- 屏幕文字：全因果注意力：算 T(T+1)/2 对，存 T 个位置
- 旁白：先看全注意力。第 i 个 token 要和前面所有 token 算一遍分数，整张表是一个下三角，面积跟长度的平方成正比。decode 的时候，每生成一个新 token，都要把全部历史的 K 和 V 读一遍，缓存也跟着长度一起长。一百二十八 K 的上下文，这两笔账都很重。

### S03 滑动窗口：只看最近 W 个
- 画面：同一个矩阵，下三角淡去，只保留对角线附近宽度 W = 4 的一条带（紫色）；右侧写出掩码公式。
- 屏幕文字：滑动窗口：j ≤ i 且 i − j < W
- 旁白：滑动窗口注意力的想法很朴素：每个 token 只看最近的 W 个位置，包括它自己。掩码从一个三角形变成一条斜着的带子，公式只多了一个条件：{i − j < W|i 减 j 小于 W}。代码里就是在因果掩码上再与一个条件。带子的宽度固定，所以每个 token 的计算量不再随长度增长。

### S04 省了多少
- 画面：两行数字对比：T = 1024 时 524,800 对 vs 4,090 对（128 倍）；T = 32768 时 4,096 倍。
- 屏幕文字：W = 4：T = 1024 省 128 倍；T = 32768 省 4,096 倍
- 旁白：数一数就知道差距。长度一千零二十四、窗口是四的时候，全注意力要算五十二万多对，滑动窗口只有四千多对，差一百二十八倍。长度到三万两千，差距变成四千多倍。窗口固定，长度越长，省得越多。当然，真实模型的窗口不会只有四，而是几百到几千，但道理一样：只要上下文比窗口长得多，就能省下一大截。

### S05 感受野：一层层接力
- 画面：横轴是位置 0–63，纵轴是层 1–6。最后一个 token 能"间接看到"的范围逐层向左扩展，每层多 3 格；另一组把第 3、6 层换成全局，第 3 层一下子铺满整行。
- 屏幕文字：只用滑动窗口：l 层感受野 = l × (W − 1)；插一层全局：一步到头
- 旁白：但是只看附近，远处的信息就彻底丢了吗？不完全是。第一层里，位置 i 看到了它前面三个；到了第二层，它看到的那些 token 本身又看过更前面的三个。信息像接力一样一层层往前传，每层多传 W 减一个位置。窗口四、六层，最远能到十八。Mistral 7B 就是这么算的：窗口四千零九十六、三十二层，理论跨度约十三万。可如果把第三层和第六层换成全注意力，第三层之后就一步看到了开头。

### S06 KV cache 封顶
- 画面：左边一个环形缓冲区示意（W 个槽位，新的覆盖最旧的）；右边三组柱子随生成长度（16、64、128、256、306）增长：full 越来越高，sliding 保持不变，interleave 缓慢增长。下方一行"与不用缓存逐字相同：True"。
- 屏幕文字：滑动窗口层只存最近 W 个 K/V
- 旁白：滑动窗口还带来一个好处：窗口外的 K 和 V 再也不会被用到，可以直接扔掉。缓存变成一个只有 W 个槽位的环，新来的覆盖最旧的。我们用训练好的小模型生成三百个字符，截断缓存和不用缓存生成的文字逐字相同。全注意力的缓存从四万九千字节涨到九十四万，纯滑动窗口从头到尾都是四万九千字节。

### S07 真实模型怎么配
- 画面：四条色带，每格是一层，紫色 = 全局、蓝色 = 局部：Mistral 7B v0.1（全蓝，W 4096）、gpt-oss（蓝紫交替，W 128）、OLMo 3（三蓝一紫，W 4096）、Gemma 3（五蓝一紫，W 1024）。
- 屏幕文字：局部-全局交替：大部分层只看附近，少数层看全部
- 旁白：真实模型很少只用滑动窗口。最早的 Mistral 7B 是全部滑动，但后来的版本把它关掉了。现在的主流做法是局部和全局交替：gpt-oss 一层局部一层全局，窗口只有一百二十八；OLMo 3 是三层局部配一层全局；Gemma 3 更激进，五层局部配一层全局，窗口一千零二十四。这些数字都写在它们的配置文件里：{layer_types|layer types} 和 {sliding_window|sliding window}。

### S08 账本：128K 省多少
- 画面：四组横条，灰色是"每层都用全注意力"，彩色是实际配置，右边标省下的百分比。
- 屏幕文字：128K 上下文、BF16 的 KV cache
- 旁白：拿第二十一章的账本算一下一百二十八 K 上下文。Gemma 3 二十七 B，如果每层都用全注意力要六十二 GiB，实际配置只要十点四 GiB，省了八成三。gpt-oss 一半层局部，正好省一半。局部层的比例越高、窗口越小，省得越多。Mistral 七 B 全部滑动，省得最狠，接近百分之九十七；而全局层那一部分，不管怎么配，都还是随长度一起涨。

### S09 实验一：loss 看不出区别
- 画面：表格：full 1.797、sliding 1.745、interleave 1.748；三者几乎一样。
- 屏幕文字：字符级语言建模：三种配置 loss 差不多
- 旁白：代价是什么？我们在 CPU 上训练三个四层的小模型：全注意力、全部滑动窗口、三层局部加一层全局，窗口都是十六。先看语言建模的验证 loss：一点七九七、一点七四五、一点七四八，几乎一样，纯滑动窗口甚至略好一点。对预测下一个字符来说，附近的上下文已经够用了。只看 loss，你会觉得滑动窗口毫无代价。纯滑动窗口略好一点，是因为这么小的模型、这么短的训练，“只看附近”反而是一个有用的先验，不能推广到大模型。

### S10 实验二：大海捞针
- 画面：坐标系，横轴是"针"与提问的距离 d（1–95），纵轴是准确率；三条线：full 与 interleave 贴在 100%，sliding 在 d = 60 之后掉到 12.5% 左右的虚线附近；竖线标出 W = 16 和感受野 60。
- 屏幕文字：纯滑动窗口在 d > 4 × (16 − 1) = 60 之后只能瞎猜
- 旁白：换一个任务：在一串随机字符里藏一根针，最后问它是哪个。全注意力在所有距离上都是百分之百。纯滑动窗口在六十以内也是百分之百，模型确实学会了一层层接力；可距离一超过六十，也就是四层乘以十五，准确率立刻掉到瞎猜的一成多。只把最后一层换成全局，所有距离又回到百分之百。这就是为什么真实模型都要留全局层：远处的检索全靠它们。

### S11 稀疏注意力：按内容挑
- 画面：注意力矩阵的一行：左边"最近 k 个"是贴着对角线的连续几格；右边"分数最高的 k 个"是散落在整行上的几格，其中一格落在很远的针上。下方数字对比。
- 屏幕文字：同样只看 k 个键：按位置挑 vs 按内容挑
- 旁白：还有一条路：既然每个 token 只看得起 k 个键，为什么非要是最近的 k 个？不如挑最相关的 k 个。我们拿训练好的全注意力模型，推理时每个 query 只留八个键。留最近八个，远处的针完全找不到；留分数最高的八个，所有距离依然百分之百。这就是稀疏注意力的核心想法：按内容挑，而不是按位置挑。

### S12 稀疏注意力的共识与代价
- 画面：四个家族徽标式文字块：DeepSeek（DSA）、GLM-5（DSA）、MiniMax-M3（MSA）、LongCat-2.0（LSA）；下方流程：便宜的索引器打分 → 选 top-k → 只对选中的做精确注意力；旁边注明"KV cache 仍全部保留"。
- 屏幕文字：索引器打分 → 选 top-k → 精确注意力；省算力，不省 KV cache
- 旁白：当然，先把全部分数算出来再挑，一点也没省。真实系统用一个很小的索引器来打分，再只对选中的几千个 token 做精确注意力。到二〇二六年九月，DeepSeek、智谱 GLM、MiniMax、美团 LongCat 的旗舰模型都用上了这类稀疏注意力，满足我们"至少三家"的共识标准。但要注意两点：它们全是两千亿参数以上的大模型，而且 KV cache 一个也不能扔，因为你不知道将来哪个 token 会被选中。它省的是算力，不是显存。

### S13 从极简到生产级
- 画面：左边极简代码的两行掩码；右边 `zero/arch/sliding_window.py` 的三个名字：`make_layer_types`、`SlidingWindowAttention`、`SlidingWindowKVCache`，以及 FlashAttention 的 `window_size`；最后出现"下一章：线性注意力与混合架构"。
- 屏幕文字：掩码 + 分层 KV cache；GPU 上用 FlashAttention 的 window_size（尚未在 GPU 上验证）
- 旁白：落到生产级代码，还是这两件事：一个多加一个条件的掩码，和一个按层区分的 KV cache，滑动窗口层用环形缓冲区，全局层照常增长。测试保证窗口覆盖全文时和全注意力完全一致，环形缓存生成和不用缓存逐字相同。到了 GPU 上，要用 {FlashAttention|flash attention} 的窗口参数才能真正跳过窗口外的计算。下一章，我们走另一条路：干脆不存 K 和 V，把历史压进一个固定大小的状态。

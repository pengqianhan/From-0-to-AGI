这是整门课的第一章。我们最后要讲到的是几千亿参数的大语言模型，但起点是一条直线：`y = ax + b`。这不是客套。**训练一个大模型，和这一章做的事情在结构上一模一样**，只是参数从 2 个变成了几十亿个。把这一章吃透，后面每一章都是在回答"同一件事做大了会遇到什么新问题"。

## 1. 直觉：什么叫"训练"

假设你手里有一批数据：每个点是 `(x, y)`，比如 x 是房子的面积，y 是价格。把它们画出来，大致排成一条斜线，但又不完全在一条线上——现实数据总有噪声。

你想要一个**模型**：给它一个新的 x，它能猜出 y。最简单的猜法是画一条直线：

```
ŷ = a·x + b
```

这里 `ŷ`（读作"y hat"）表示模型的**预测**，`a` 是斜率，`b` 是截距。`a` 和 `b` 叫作模型的**参数（parameter）**——模型的全部"知识"都装在这两个数里。

问题是：a 和 b 该取多少？

"训练"就是**让数据来决定参数**。具体分四步，这四步贯穿整门课：

1. **模型**：写出预测的公式，`ŷ = a·x + b`。
2. **损失（loss）**：用一个数衡量"猜得有多差"。
3. **梯度（gradient）**：算出"参数往哪个方向动，损失会变小"。
4. **更新（update）**：让参数朝那个方向走一小步。然后回到第 1 步，重复。

## 2. 损失：把"猜得有多差"变成一个数

对第 i 个数据点，模型的预测是 `ŷ_i = a·x_i + b`，真实值是 `y_i`，差距 `ŷ_i − y_i` 叫**残差**。把所有点的残差平方后取平均，就是**均方误差（Mean Squared Error, MSE）**：

```
L(a, b) = 1/N · Σ (a·x_i + b − y_i)²
```

为什么要平方？两个原因：一是让正负误差不会互相抵消；二是平方函数处处光滑，方便求导——这一点马上就要用到。

注意 `L` 写成了 `L(a, b)`：**数据是固定的，损失是参数的函数**。换一组 a、b，就得到另一个损失值。如果把所有 (a, b) 组合对应的损失画出来，会得到一个碗形的曲面，我们要找的就是碗底。

## 3. 梯度：往哪个方向走，损失下降最快

想象你站在一个碗形山谷的坡上，四周全是雾，看不到谷底。你能做的只有一件事：感受脚下的坡度，然后往下坡最陡的方向迈一步。

**梯度**就是"脚下的坡度"。它是损失对每个参数的偏导数组成的向量，指向损失**上升**最快的方向。对我们的 MSE，用链式法则可以直接算出来：

```
∂L/∂a = 2/N · Σ (ŷ_i − y_i) · x_i
∂L/∂b = 2/N · Σ (ŷ_i − y_i)
```

读一下这两个公式的含义：如果模型整体猜高了（残差大多为正），`∂L/∂b` 就是正的，说明 b 应该减小；残差和 x 的乘积告诉我们斜率 a 是该调大还是调小。梯度不是一个抽象符号，它就是"模型错在哪、错了多少"的汇总。

## 4. 更新：梯度下降

既然梯度指向上坡，我们就往反方向走：

```
a ← a − η · ∂L/∂a
b ← b − η · ∂L/∂b
```

`η`（读作"eta"）叫**学习率（learning rate）**，控制每一步迈多大。这个"算梯度 → 反方向走一小步 → 重复"的过程，就是**梯度下降（Gradient Descent）**。

## 5. 极简代码：60 行拟合一条直线

运行：

```bash
uv run python chapters/01-linear-regression/code/01_fit_line.py
```

核心只有这几行（完整代码见 [`code/01_fit_line.py`](code/01_fit_line.py)）：

```python
def gradients(a, b, x, y):
    err = (a * x + b) - y              # 残差 ŷ_i − y_i
    grad_a = 2 * np.mean(err * x)      # ∂L/∂a
    grad_b = 2 * np.mean(err)          # ∂L/∂b
    return grad_a, grad_b

for _ in range(steps):
    grad_a, grad_b = gradients(a, b, x, y)
    a = a - lr * grad_a                # a ← a − η · ∂L/∂a
    b = b - lr * grad_b                # b ← b − η · ∂L/∂b
```

我们造的数据真实关系是 `y = 2x + 1`，再加上噪声。从一个很差的起点 `a = −1, b = 4` 出发，学习率 0.05，输出如下：

| 步数 | a | b | 损失 |
|---:|---:|---:|---:|
| 0 | −1.000 | 4.000 | 44.23 |
| 1 | 0.944 | 4.492 | 3.34 |
| 10 | 1.166 | 3.855 | 2.33 |
| 50 | 1.682 | 2.123 | 0.61 |
| 200 | 2.038 | 0.926 | 0.25 |

几个值得注意的现象：

- **第一步损失就从 44 掉到 3.3**：一开始离谷底很远，坡很陡，梯度很大，一步就走了很远。
- **后面越走越慢**：接近谷底时坡变缓，梯度变小，步子也跟着变小。
- **最后停在 a ≈ 2.04、b ≈ 0.93，不是精确的 2 和 1**：因为数据有噪声。和最小二乘的解析解（`np.polyfit` 给出 a = 2.052、b = 0.879）对比，梯度下降正在朝同一个点收敛。

> **既然线性回归有解析解，为什么还要梯度下降？** 因为只有线性模型这么幸运。从第 3 章的神经网络开始，就再也没有"一步到位"的公式了，梯度下降是唯一通用的办法。今天用它解一个我们知道答案的问题，就是为了看清它是怎么工作的。

## 6. 学习率：太小、刚好、太大

学习率是训练里最重要的一个旋钮。运行：

```bash
uv run python chapters/01-linear-regression/code/02_learning_rate.py
```

输出（都是走 100 步）：

| 学习率 η | 100 步后的损失 | 结果 |
|---:|---:|---|
| 0.005 | 2.34 | 太小：方向对，但走得太慢 |
| 0.05 | 0.29 | 正常收敛 |
| 0.0914 | 0.25 | 接近临界值，收敛最快 |
| 0.1066 | 7.7 × 10⁹ | 太大：来回震荡，越震越远，发散 |

临界值是怎么来的？对这个问题，损失是 a、b 的二次函数，碗的形状完全由数据决定。数学上可以证明，梯度下降在二次函数上收敛的条件是 `η < 2/λ_max`，其中 `λ_max` 是损失二阶导数矩阵（Hessian）的最大特征值，可以理解为"碗最陡那个方向的弯曲程度"。代码里直接算出这个临界值是 0.1016，实验结果和理论完全吻合：比它小一点就收敛，比它大一点就发散。

这个现象会一路跟着我们：训练大模型时的 loss 突然爆炸（loss spike），很多时候也是"在某个方向上步子迈大了"。第 6 章会讲 warmup 和学习率衰减，本质上都是在管理这个旋钮。

## 7. 小结

- **模型**：`ŷ = a·x + b`，参数是 a 和 b。
- **损失**：均方误差 `L(a, b)`，数据固定时它是参数的函数。
- **梯度**：`∂L/∂a`、`∂L/∂b`，指向损失上升最快的方向。
- **更新**：`参数 ← 参数 − η · 梯度`，重复直到损失不再下降。
- **学习率**：太小走得慢，太大会发散。

## 从极简到生产级

极简版里，梯度是我们手推公式算出来的。真实的深度学习代码不会这样写：模型一复杂，手推梯度既累又容易错。同一件事的 PyTorch 标准写法在 [`code/03_pytorch_version.py`](code/03_pytorch_version.py)：

```python
model = nn.Linear(in_features=1, out_features=1)   # 权重就是 a，偏置就是 b
optimizer = torch.optim.SGD(model.parameters(), lr=0.05)
loss_fn = nn.MSELoss()

for step in range(201):
    y_hat = model(x)              # 1. 前向：算预测
    loss = loss_fn(y_hat, y)      # 2. 损失
    optimizer.zero_grad()         # 3. 清掉上一步的梯度
    loss.backward()               # 4. 反向：autograd 自动求梯度
    optimizer.step()              # 5. 更新参数
```

它比极简版多做了什么，为什么要多做：

| 极简版 | 生产级写法 | 为什么 |
|---|---|---|
| 手推 `∂L/∂a`、`∂L/∂b` | `loss.backward()` 自动求梯度 | 模型有几十亿参数时不可能手推；第 4 章会亲手实现 autograd，看清它的原理 |
| `a = a - lr * grad_a` | `optimizer.step()` | 更新规则会变复杂（第 6 章的 AdamW），交给优化器统一管理 |
| 两个浮点数 a、b | `nn.Linear` 里的权重张量 | 第 2 章会把一个输入扩展成很多个输入，权重变成矩阵 |
| 无 | `optimizer.zero_grad()` | PyTorch 默认把梯度**累加**起来（这在第 14 章的梯度累积里是有用的特性），所以每步开始前要手动清零 |

脚本最后把 PyTorch 版和手算版的结果放在一起：201 步之后两者都是 `a = 2.039, b = 0.925`，**逐位一致**。这就是后面每一章都会做的事——生产级代码必须和极简版"对拍"，结果对得上，才能相信它。

这五行训练循环值得记住。第 14 章预训练主线模型时，循环外面会多出分布式、混合精度、断点续训这些工程细节，但循环的骨架仍然是这五步。

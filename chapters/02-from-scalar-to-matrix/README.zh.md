上一章我们用 `ŷ = a·x + b` 学会了训练的四个步骤：模型、损失、梯度、更新。但那个模型只有**一个输入**和**两个参数**。在真实世界里，房价不只取决于面积。大语言模型的一层，输入是几千维的向量。这一层还要同时处理成百上千个样本。

这一章回答一个问题：**输入从一个数变成一组数，样本从一个变成一批，模型和训练该怎么写？**答案是向量和矩阵。四个步骤一个都不变，只是把标量换成矩阵。换完之后，代码更短，运行也更快。

## 1. 直觉：一个输入不够

还是预测房价。第 1 章只用面积 x。现在每套房子有三个特征（feature）：

| 特征 | 例子 |
|---|---|
| x₁ 面积 | 80 ㎡ |
| x₂ 卧室数 | 2 间 |
| x₃ 距市中心 | 5 km |

最自然的推广是：给每个特征配一个**权重**（weight）。权重表示这个特征对价格的影响有多大。再加上一个偏置（bias）b：

```
ŷ = w₁·x₁ + w₂·x₂ + w₃·x₃ + b
```

第 1 章的斜率 a，就是"只有一个特征时的权重"。假设每平米值 0.8 万，每间卧室值 5 万，离市中心每远 1 公里少 3 万，底价 20 万。这套房子的预测就是 `0.8×80 + 5×2 − 3×5 + 20 = 79` 万。

问题来了：特征不止 3 个时（大模型里有几千个），要一项一项写下去吗？我们需要一种记号，把"一组数"当成一个整体来操作。

## 2. 向量与点积

把三个特征排成一列，叫作**向量**（vector）：`x = [80, 2, 5]`。三个权重也排成一个向量：`w = [0.8, 5, −3]`。上面那一长串乘加就是**点积**（dot product）：对应位置相乘，再全部加起来。

```
w · x = w₁x₁ + w₂x₂ + w₃x₃ = Σ wᵢxᵢ
ŷ = w · x + b
```

运行：

```bash
uv run python chapters/02-from-scalar-to-matrix/code/01_matrix_basics.py
```

对应的代码（[`code/01_matrix_basics.py`](code/01_matrix_basics.py)）：

```python
dot_loop = sum(w[i] * x[i] for i in range(3))   # Σ wᵢxᵢ, one term at a time
dot_np = w @ x                                  # the same calculation in one line of NumPy
```

输出：`w · x = 59.0`，`ŷ = w · x + b = 79.0`。

点积还有一个几何意义，后面会多次用到。两个向量方向越一致，点积越大。两个向量互相垂直时，点积为 0。第 8 章的注意力机制用点积衡量"两个词有多相关"。

## 3. 一批样本：矩阵

一套房子做一次点积。一万套房子呢？把每套房子的特征向量当作一**行**，再把这些行摞在一起，就得到一个**矩阵**（matrix）X：

```
        面积  卧室  距离
X = [[  80,   2,   5.0],    ← 第 1 套房子
     [ 120,   3,   2.0],    ← 第 2 套
     [  60,   1,   8.0],    ← 第 3 套
     [ 100,   3,   3.5]]    ← 第 4 套         形状 (4, 3)
```

**每一行是一个样本，每一列是一个特征。**形状（shape）写成 `(行数, 列数)` = `(4, 3)`。

把权重竖着排成一列 W（形状 `(3, 1)`）。一次**矩阵乘法** `X @ W` 就同时算出四套房子的点积：

```python
scores = X @ w          # (4, 3) @ (3,) → (4,)
scores + b              # [ 79. 125.  49. 104.5]
```

这四个数就是四套房子的预测价格。**一次矩阵乘法 = 每个样本各做一次点积。**

## 4. 矩阵乘法怎么算，形状规则从哪来

矩阵乘法 `C = A @ B` 的定义只有一句话：

```
C[i][j] = A 的第 i 行 · B 的第 j 列
```

最直接的实现是三重循环（[`code/02_matrix_multiply.py`](code/02_matrix_multiply.py)）：

```python
for i in range(m):              # row i of the result
    for j in range(n):          # column j of the result
        for p in range(k):      # dot product of row i and column j
            C[i][j] += A[i][p] * B[p][j]
```

运行 `uv run python chapters/02-from-scalar-to-matrix/code/02_matrix_multiply.py`。脚本会打印每一格的计算过程：

```
C[0][0] = 1×7 + 2×9 + 3×11 = 58
C[0][1] = 1×8 + 2×10 + 3×12 = 64
C[1][0] = 4×7 + 5×9 + 6×11 = 139
C[1][1] = 4×8 + 5×10 + 6×12 = 154
```

从定义直接得到这一章最重要的规则：**形状规则**。

```
(m, k) @ (k, n) → (m, n)
```

- 中间的两个 k 必须相等。A 的一行和 B 的一列要做点积，两个向量必须一样长。
- 结果的行数来自 A，列数来自 B。中间的 k 在求和时"消掉"了。

脚本最后验证了三个例子：

| 左 | 右 | 结果 |
|---|---|---|
| (4, 3) | (3, 1) | (4, 1) |
| (32, 128) | (128, 64) | (32, 64) |
| (3, 2) | (3, 5) | 报错：中间的 2 ≠ 3 |

深度学习代码里，很多 bug 来自形状不匹配。请养成习惯：每写一行矩阵运算，就在注释里写下形状。

> **注意：**`@` 和 `*` 是两种不同的运算。`A @ B` 是矩阵乘法。`A * B` 是**元素级乘法**（element-wise multiplication，也叫 Hadamard 乘积）：对应位置相乘。在 `01_matrix_basics.py` 里，`M @ N = [[19, 22], [43, 50]]`，`M * N = [[5, 12], [21, 32]]`。两个形状相同时，两种运算都不报错，结果却完全不同。这是最难查的一类 bug。

## 5. Y = XW + b：给每个字母标上形状

把第 3 节推广到"多个输出"，就得到神经网络里最常见的一行：

```
Y   =   X    @   W    +   b
(N,n)  (N,k)    (k,n)    (n,)
```

- **N**：这一批的样本数，叫作**batch 维**（batch dimension）。
- **k**：每个样本的输入特征数。
- **n**：输出个数。W 的**第 j 列**是计算第 j 个输出用的 k 个权重。

一个关键观察：**W 的形状和 N 无关**。一次输入 4 个样本还是 1 万个样本，用的都是同一个 W。所以训练时可以改变 batch 大小，而不用改模型。

[`code/03_linear_layer.py`](code/03_linear_layer.py) 把 4 套房子依次送进两层：

```python
def linear(X, W, b):
    return X @ W + b            # (batch, k) @ (k, n) + (n,) → (batch, n)
```

```
(4, 3) --[@W1 + b1]--> (4, 2) --[@W2 + b2]--> (4, 1)
```

### 广播：b 怎么加到每一行

`X @ W` 的形状是 `(N, n)`，而 b 的形状只有 `(n,)`。形状不同，怎么相加？NumPy 和 PyTorch 会自动把 b 加到**每一行**上。效果相当于把 b 复制 N 份，但内存里并没有真的复制。这叫作**广播**（broadcasting）。

规则：两个形状**从最后一维开始对齐**。每一维的两个大小要么相等，要么其中一个是 1（或者缺失），才能广播。`01_matrix_basics.py` 的输出：

```
(4, 2) matrix + vector of shape (2,) → [10, -1] is added to each row
(4, 2) + (3,) gives an error: operands could not be broadcast together with shapes (4,2) (3,)
```

所以 b 的长度必须等于输出个数 n。广播很方便，也很危险。两个形状可能"碰巧"能广播。这时代码不报错，算的却可能完全不是你想要的东西（见引导问题 4）。

## 6. 梯度也写成矩阵

模型变成了 `ŷ = XW + b`，损失还是均方误差 `L = 1/N · Σ (ŷᵢ − yᵢ)²`。梯度怎么算？

回忆第 1 章：`∂L/∂a = 2/N · Σ (ŷᵢ − yᵢ) · xᵢ`。现在有 k 个权重，第 j 个权重的梯度形式相同：

```
∂L/∂w_j = 2/N · Σᵢ (ŷᵢ − yᵢ) · x_ij
```

把 j = 1…k 的梯度摞成一列，正好是矩阵乘法 `Xᵀ @ (ŷ − y)`，因为 Xᵀ 的第 j 行就是所有样本的第 j 个特征。于是：

```
∂L/∂W = 2/N · Xᵀ (ŷ − y)        (k, N) @ (N, 1) → (k, 1)
∂L/∂b = 2/N · Σ (ŷ − y)
```

检查形状：结果是 `(k, 1)`，和 W 相同。**梯度和参数的形状总是相同**，因为每个参数都需要自己的梯度。以后遇到更复杂的公式，先用形状检查一遍。这一步能挡掉一半错误。

`Xᵀ` 是 X 的**转置**（transpose）：行变成列，列变成行。`(N, k)` 变成 `(k, N)`。

## 7. 极简代码：训练多元线性回归

运行：

```bash
uv run python chapters/02-from-scalar-to-matrix/code/04_multivariate_regression.py
```

核心代码和第 1 章几乎相同（[`code/04_multivariate_regression.py`](code/04_multivariate_regression.py)）：

```python
def gradients(W, b, X, y):
    n = len(X)
    err = X @ W + b - y                  # (N, 1): residual ŷ − y
    grad_W = 2 / n * X.T @ err           # ∂L/∂W = 2/N · Xᵀ(ŷ − y), (3, 1)
    grad_b = 2 / n * err.sum(axis=0)     # ∂L/∂b = 2/N · Σ(ŷ − y)
    return grad_W, grad_b

for _ in range(steps):
    grad_W, grad_b = gradients(W, b, X, y)
    W = W - lr * grad_W                  # W ← W − η · ∂L/∂W
    b = b - lr * grad_b                  # b ← b − η · ∂L/∂b
```

我们造了 200 套房子。真实规律是 `价格 = 0.8·面积 + 5·卧室 − 3·距离 + 20`，再加上标准差为 5 万的噪声。

**先标准化。**三个特征的尺度差别很大：标准差分别是 30.14、1.11、5.19。用第 1 章的方法算临界学习率 `2/λ_max`：

| | 临界学习率 |
|---|---:|
| 原始特征 | 8.45 × 10⁻⁵ |
| 标准化后（每个特征减去均值，再除以标准差） | 0.879 |

用原始特征时，"碗"在面积方向上又窄又陡，所以学习率必须小于万分之一。最平缓的方向几乎就是偏置 b 的方向。它的弯曲程度只有最陡方向的约二十四万分之一。用这么小的学习率，要走几十万步才能到达碗底（动手任务 2 让你亲眼看到这一点）。

**标准化**（standardization）让每个方向的弯曲程度差不多，学习率就可以大很多。这是第 1 章引导问题 3 的答案，也是第 6 章"归一化"的前身。

从 W = 0、b = 0 出发，学习率取 0.1（参数在标准化空间里）：

| 步数 | w_面积 | w_卧室 | w_距离 | b | 损失 |
|---:|---:|---:|---:|---:|---:|
| 0 | 0.000 | 0.000 | 0.000 | 0.000 | 7875.146 |
| 1 | 5.014 | 1.332 | −3.077 | 16.682 | 5043.738 |
| 10 | 22.021 | 5.039 | −14.099 | 74.455 | 112.024 |
| 20 | 24.297 | 5.260 | −15.718 | 82.450 | 22.981 |
| 50 | 24.571 | 5.248 | −15.918 | 83.410 | 21.942 |
| 200 | 24.571 | 5.248 | −15.918 | 83.411 | 21.942 |

换算回原始单位（万元）：

| | 梯度下降 | 解析解（最小二乘） | 真实值 |
|---|---:|---:|---:|
| w_面积（每㎡） | 0.815 | 0.815 | 0.800 |
| w_卧室（每间） | 4.734 | 4.734 | 5.000 |
| w_距离（每 km） | −3.070 | −3.070 | −3.000 |
| b | 19.837 | 19.837 | 20.000 |

请看这几个结果：

- **50 步就收敛了**，和第 1 章一样：先大步下降，然后越走越慢。
- **最终损失 21.94，接近噪声方差 5² = 25。**模型学到了规律。剩下的是数据本身的噪声，任何模型都消除不了。
- **梯度下降和解析解到小数点后三位完全一致。**和真实值的小偏差来自噪声。
- 用学到的模型预测一套新房子（100 ㎡、3 室、距市中心 5 km）：100.2 万元。

## 8. 循环 vs 向量化：差多少

同一个公式，可以用 Python 循环一项一项地算，也可以用一次矩阵运算算完。后者叫作**向量化**（vectorization）。运行：

```bash
uv run python chapters/02-from-scalar-to-matrix/code/05_loop_vs_vectorized.py
```

脚本先核对几种写法的结果一致，再计时（取多次运行中最快的一次）。本机（4 核 CPU）一次运行的结果如下：

**对比 1：一次前向传播 `Y = X @ W`，X 是 (1000, 100)，W 是 (100, 10)**

| 写法 | 耗时 | 相对三重循环 |
|---|---:|---:|
| Python 三重循环（`02` 里的 `matmul`） | 62.70 ms | 1× |
| 只循环样本，每行一次 `np.dot` | 1.94 ms | 快 32 倍 |
| 一次 `X @ W` | 0.057 ms | 快 1091 倍 |

**对比 2：多元线性回归（5000 套房子，3 个特征）训练 200 步**

| 写法 | 耗时 |
|---|---:|
| 逐样本、逐特征循环算梯度 | 538.99 ms |
| 矩阵形式 `2/N · Xᵀ(ŷ − y)` | 21.73 ms（快 25 倍） |

两种训练写法学到的参数最大差 3.6 × 10⁻¹⁵，这是浮点误差。计时随机器和负载变化。同一台机器多跑几次，前向对比的倍数在 950–1170 倍之间波动。2026-10 换一台服务器复跑，前向对比是 1400–1650 倍，训练对比约 50 倍。机器同时忙别的事（比如渲染视频）时，还会更慢。看数量级即可。

对比 2 只快了几十倍（具体多少取决于机器），比对比 1 的上千倍少得多。这个差别本身说明了问题。这里每次矩阵运算只处理 5000×3 个数，还有 200 次 Python 层面的循环和函数调用。**每次交给底层库的工作越多，向量化的优势越明显。**这也是 GPU 训练要用大 batch 的原因之一。

**为什么快？**Python 循环每做一次乘加，都要解释一行代码、检查类型、创建新的数字对象。真正的计算只占很小一部分。`X @ W` 则把整块数据交给用 C 和汇编写成的线性代数库（BLAS）。数据在内存里连续存放。一条 CPU 指令能同时算好几个数（SIMD），线性代数库还能用上多个核心。

到了 GPU 上，成千上万个核心同时做乘加，而 GPU 最擅长的正是矩阵乘法。大模型训练和推理的大部分计算量都在矩阵乘法里（第 12 章估算训练算力的 `C ≈ 6ND`，主要数的就是矩阵乘法里的乘加次数）。所以整个深度学习都写成矩阵的形式。

## 9. 小结

- **一组输入 → 向量**：`ŷ = w · x + b`。点积 = 对应位置相乘，再求和。
- **一批样本 → 矩阵**，每行一个样本：`Y = XW + b`，形状 `(N, k) @ (k, n) + (n,) → (N, n)`。
- **形状规则** `(m, k) @ (k, n) → (m, n)`：中间的两个 k 必须相等。
- **广播**：b 从最后一维对齐，自动加到每一行。
- **梯度** `∂L/∂W = 2/N · Xᵀ(ŷ − y)`：和 W 同形状。
- **向量化**：同一个计算，一次矩阵运算比 Python 循环快几十到上千倍。
- 训练的四个步骤（模型、损失、梯度、更新）一个都没变。

## GPU 实测（单张 RTX 3090）

这张表把第 8 节的结论又演示了一遍，只是主角换成了 GPU：每次交给底层库的工作越多，向量化的优势越明显。N ≤ 512 时，GPU 那一列几乎不变，一直是 0.02–0.04 ms。这是"启动一次 GPU 计算、再等它返回"的固定开销。这个开销和矩阵大小无关。所以 64、128 这样的小矩阵，CPU 反而更快。

N 到了 1024 以上，固定开销被摊薄。这时 GPU 快 38–51 倍，BF16 张量核又比 float32 快 2–3 倍。这个结果支持两个说法："GPU 训练要用大 batch"，以及"从极简代码到生产级代码"表格里的"第 14 章还会降到 BF16"。GPU 要处理足够大的矩阵，才能被充分利用。

有一个结果出乎意料：float32 在 2048 时最快，更大的矩阵反而降到 17 TFLOPS 左右，只有规格表的一半。原因是服务器把这张卡的功耗上限设成了 240 W（出厂默认 350 W）。我们另外连续跑了几秒大矩阵乘法。功耗一直顶在 240 W，核心频率从空闲时的约 1.7 GHz 降到 0.8–1.0 GHz。算得越久，频率压得越低。所以在你自己的卡上，大矩阵这几行的数字多半会更好。

## 从极简代码到生产级代码

同一件事的 PyTorch 标准写法在 [`code/06_pytorch_version.py`](code/06_pytorch_version.py)。模型换成 `nn.Linear(3, 1)`。训练循环和第 1 章的五行**完全相同**：

```python
model = nn.Linear(in_features=3, out_features=1)   # linear layer with 3 inputs and 1 output
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
loss_fn = nn.MSELoss()

for step in range(200):
    y_hat = model(x)              # 1. forward pass: (200, 3) → (200, 1), the full batch at one time
    loss = loss_fn(y_hat, t)      # 2. loss
    optimizer.zero_grad()         # 3. set the gradients to zero
    loss.backward()               # 4. backward pass: autograd calculates ∂L/∂W = 2/N·Xᵀ(ŷ−y)
    optimizer.step()              # 5. update
```

运行 `uv run python chapters/02-from-scalar-to-matrix/code/06_pytorch_version.py`，输出：

```
nn.Linear(3, 1): weight shape (1, 3), bias shape (1,)
Input batch (4, 3) → output (4, 1); maximum difference from x @ weight.T + bias 0.0e+00
...
After 200 steps (standardized space):
  PyTorch  W = [ 24.571   5.248 -15.918], b = [83.411]
  NumPy    W = [ 24.571   5.248 -15.918], b = [83.411]
  float64 maximum difference = 0.0e+00
  float32 (default precision of PyTorch) maximum difference = 1.8e-05
```

下表列出生产级代码多做了什么，以及原因：

| 极简代码 | 生产级代码 | 原因 |
|---|---|---|
| 手工推导 `grad_W = 2/N * X.T @ err` | `loss.backward()` | 这一章的梯度还能手工推导。第 3 章加入非线性，层数一多，就无法手工推导。第 4 章你会自己实现 autograd。 |
| W 的形状是 `(k, n)`，计算 `X @ W` | `weight` 的形状是 `(n, k)` = `(输出, 输入)`，计算 `x @ weight.T + bias` | 这是 PyTorch 的约定，文档写作 `y = xAᵀ + b`。读别人的代码、加载别人的权重时，一定要注意这个转置。 |
| 输入必须是 `(N, k)` | 输入可以是 `(*, k)`：前面可以有任意多个维度 | 第 9 章的 Transformer 里，输入是 `(batch, 序列长度, 维度)`。`nn.Linear` 只作用在最后一维。 |
| float64 | 默认 float32 | 单精度省一半内存，在 GPU 上快得多。代价是约 10⁻⁵ 量级的数值差（上面的 1.8e-05）。第 14 章还会降到 BF16。 |

**对拍**：用 float64 时，PyTorch 版和手写矩阵梯度的 NumPy 版在 200 步后**完全相同**（差为 0）。用默认的 float32 时，差在 10⁻⁵ 量级。生产级代码和极简代码结果一致，才能信任生产级代码。

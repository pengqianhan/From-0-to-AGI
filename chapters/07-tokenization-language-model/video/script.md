## 二、分镜与旁白

### S01 片头
- 画面：标题卡"第 7 章 / 语言建模与分词"。
- 屏幕文字：第 7 章 · 语言建模与分词
- 旁白：第二部分开始了。这一部分我们要亲手搭一个现代的语言模型。第一个问题很基础：模型只认识数字，一段文字到底要怎么变成数字？这一章讲清楚分词，再做一个最简单的语言模型，并学会怎么公平地给它打分。

### S02 语言模型：猜下一个 token
- 画面：一句话"学 而 时 习 之"逐个出现，每个位置上方画出一个概率条形图；下方链式法则公式。
- 屏幕文字：p(x₁…x_T) = Π p(x_t | x_<t)
- 旁白：语言模型要回答的问题是：一段文本出现的概率有多大。概率论的链式法则把它拆成一串小问题：已知前面的内容，下一个 token 是什么。每个小问题，都是第五章讲过的分类，类别就是词表里的每个 token。训练目标也还是交叉熵。注意，链式法则是恒等式，不是近似。所以，语言模型的核心其实只有一件事：猜下一个 token。从最简单的计数表，到几千亿参数的大模型，区别只在于这个概率怎么算。剩下的问题是，token 到底是什么。

### S03 按字符切
- 画面：左边英文"To be"切成字符，右边中文切成字；下方表格：英文 65 种字符，中文 5,297 种字；一个红色的 <unk>。
- 屏幕文字：字符级：中文词表 5,297，且有没见过的字
- 旁白：最直接的办法是按字符切，每个不同的字符一个编号。英文莎士比亚只要六十五个字符就够了。但中文完全不同：一百多万字节的诗词里，就有五千二百九十七个不同的字。更麻烦的是，拿前百分之九十当训练集，后面百分之十里有一百九十八个字从来没见过，只能统统记成一个"未知"符号，信息就丢了。

### S04 按字节切：UTF-8
- 画面："学"拆成三个字节方块 229、173、166；"学而时习之"从 5 个方块展开成 15 个。
- 屏幕文字：字节级：词表固定 256，中文序列变长 2.8 倍
- 旁白：另一个办法是按字节切。计算机用 UTF-8 存文本，英文字母是一个字节，常用汉字是三个字节。比如"学"，就是二二九、一七三、一六六这三个数。字节只有二百五十六种，所以词表固定是二百五十六，任何文字都能编码，永远不会遇到不认识的字。代价是序列变长了：同样的中文，字节数是字数的二点八倍。下一章会看到，注意力的计算量随序列长度的平方增长，序列越长越贵。

### S05 BPE：合并最常见的一对
- 画面：「不亦说乎，」的 15 个字节方块，按学到的合并顺序逐步两两合并成更宽的方块，每次标出新 token 的编号；最后剩 6 个。
- 屏幕文字：BPE：反复把最常见的相邻一对合并成新 token
- 旁白：有没有两全其美的办法？这就是 BPE，字节对编码。从二百五十六个字节出发，统计语料里哪两个相邻的 token 一起出现得最多，就把它们合并成一个新 token，词表加一。然后再数，再合并，一直做到词表够大。编码新文本时，按学到的顺序重放这些合并。看这个例子：十五个字节，一步步合并，最后只剩六个 token。"不""亦""乎"都合成了整字，"说"还差一步，保留成两个片段。没学到的字就退回字节，不会丢信息。

### S06 最先学到的合并
- 画面：前 18 个合并分三列逐行出现：256 \xef\xbc 7,212 次、257 ␣␣、258 ，、259 \xe3\x80、260 。…；彩色框高亮四类：全角标点前缀、汉字半个字、代码缩进、英文 he。
- 屏幕文字：最先学到的合并（英文 + 中文 + 代码各 6 万字符）
- 旁白：我们在英文、中文、代码各六万字的语料上训练了七百六十八次合并。看看最先学到的是什么。第一个合并并不是一个字，而是全角标点共同的前两个字节，下一步就合成了完整的逗号。接下来很多是汉字的半个字，因为很多常用字共享同样的开头字节；还有代码里的缩进空格，英文的 h e、i n。后面学到的长 token 有 return、import，还有莎士比亚剧本里的人名。BPE 学到什么，完全取决于语料里什么多。在训练之前，还要先用一个正则表达式把文本切成单词、数字、标点这样的小块，合并不跨越小块的边界。

### S07 词表大小的取舍
- 画面：左边折线图：横轴词表大小（对数），纵轴验证集 token 数，从 97,874 降到 25,823；右边条形图：几个模型的 embedding 参数。
- 屏幕文字：词表越大 → 序列越短（收益递减），embedding 参数 V × d 越多
- 旁白：词表该多大？左边是实测：词表从二百七十二涨到一千，序列长度几乎砍掉一半；但越往后收益越小，从一万六到三万二，只少了百分之七。右边是代价：每个 token 都要一个向量，embedding 参数等于词表大小乘以宽度。千问三点五零点八B 的词表有二十四万八千，光 embedding 就约两亿五千万参数。对小模型来说，这些参数本可以放进 Transformer 层里。所以本课主线模型的词表暂定六万五千五百三十六，第十三章再实测决定。

### S08 bigram：数一数
- 画面：英文字符 bigram 计数表的热力图（10 个常见字符），行是当前字符、列是下一个字符；高亮 t→h 这一格；右边公式 p(b|a)=count(a,b)/Σcount(a,·)。
- 屏幕文字：bigram：只看前 1 个 token，数频率就是最大似然
- 旁白：有了分词器，就可以做语言模型了。最简单的是 bigram：只看前一个 token。它的参数就是一张大表，行是当前 token，列是下一个 token。训练根本不需要梯度下降，直接数：在语料里，t 后面跟 h 出现了多少次，除以 t 出现的总次数，就是最大似然的答案。为了不让没见过的组合概率变成零，每格再加一个很小的数，叫平滑。

### S09 从 bigram 里抽样
- 画面：两段抽样文本逐字打出：英文 BPE、中文字符；旁边标注"只看前 1 个 token"。
- 屏幕文字：像模像样的格式，毫无意义的内容
- 旁白：从这张表里一个接一个地抽样，就能生成文字。英文学会了剧本的格式：人名，冒号，换行。中文学会了作者名单独一行，后面接诗句。但内容毫无意义，因为它只看前一个 token，前面说过什么，它全都不记得。中文 BPE 的抽样里还偶尔会出现乱码：模型生成了一个字的前两个字节，下一步却接了一个对不上的字节。

### S10 评估：从 nats 到 bits-per-byte
- 画面：一条换算链：nats/token → ÷ln2 → bits/token → 2^ → 困惑度；再出现 bpb 公式，分母换成字节数。
- 屏幕文字：bpb = 总损失 / (ln2 × 总字节数)
- 旁白：怎么给语言模型打分？在没见过的文本上算平均交叉熵。用自然对数算，单位是 nats；除以 ln2，就是 bits；再取指数，就是困惑度。但这三个数都是"每个 token"的。不同分词器的 token 长短不一，直接比，就像比较每一步走多远，却不管步子大小。所以要换个分母：把总损失摊到原文的每个字节上，这叫 bits per byte，简称 {bpb|B P B}。同一段文本的字节数是固定的，所以它和分词器无关。

### S11 真实数字：困惑度会骗人
- 画面：英文三种分词的两组条形图：左边困惑度（字节 12.7、字符 12.7、BPE 37.0），右边 bpb（3.669、3.668、2.956）；再出现中文和代码的 bpb。
- 屏幕文字：只看困惑度，结论完全相反
- 旁白：看真实的数字。在英文上，字节级 bigram 的困惑度是十二点七，BPE 是三十七，好像字节级好得多。可换成 bpb，BPE 是二点九六，字节级是三点六七，BPE 反而好了百分之十九。因为 BPE 的一个 token 覆盖将近两个字节，看前一个 token，其实看到了更多前文。中文上结果又不同：一千的词表太小，很多字还是半个字，这时按字符切的 bpb 最低。这些结论，只有用 bpb 才看得出来。

### S12 从极简到生产级
- 画面：左边 `zero/tokenizer.py` 的几行代码（NFC、Split 正则、ByteLevel、BpeTrainer、特殊 token）；右边对拍表：手写 1.76/1.74/1.95，zero 1.86/1.79/1.97；下方"tests/test_tokenizer.py 12 项通过"。
- 屏幕文字：生产级：Rust 实现、Qwen 同款正则、特殊 token、uint32 分片
- 旁白：主线模型的分词器在 zero 的 tokenizer 点 py 里。算法和我们手写的一样，多做了几件事：用 Rust 实现的 tokenizers 库，比纯 Python 快，撑得起 GB 级的语料；预切分正则和千问完全相同，数字逐个切开；前面放了十六个特殊 token，给对话和工具调用当边界标记。同样的合并次数，两者的压缩率很接近，而且都能逐字节还原原文。分好的词再写成 uint32 分片，每篇文档末尾加一个 endoftext，让模型知道一篇文章在哪里结束。这些行为都由分词器的测试保证，十二项测试全部通过。

### S13 下一章：只看一个 token 不够
- 画面：一句"学而时习之，不亦说乎"，bigram 在"乎"上只连一条线回到"说"；然后出现许多条紫色的线连回前面所有字，写"注意力"。
- 屏幕文字：bigram 只看前 1 个 token → 注意力：看前面所有 token
- 旁白：回顾一下：语言模型就是猜下一个 token；byte-level BPE 从字节出发，把常见的片段合并成 token；比较不同分词器的模型，要看 bits per byte。bigram 最大的问题写在它的定义里：只看前一个 token。想看前两个、前三个，表的大小就变成词表的三次方、四次方，根本存不下。下一章的注意力，让每个位置都能回头看前面所有的 token。我们下一章见。

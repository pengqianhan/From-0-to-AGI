## 二、分镜与旁白

### S01 片头
- 画面：章节标题卡"第 12 章 / Scaling Law 与实验设计"，副标题"先用小模型算清楚，再花大钱"。
- 屏幕文字：第 12 章 · Scaling Law 与实验设计
- 旁白：上一章我们先定好了考卷。这一章要回答一个很现实的问题：预训练只有大约五千美元，一次机会，模型该做多大、喂多少数据、学习率取多少？答案是：先用一串小模型把规律测出来，再外推。

### S02 一次机会
- 画面：左边一个大方块"主线预训练 $5,000，10 天"，右边一排小方块"阶梯实验，每个几美元"；箭头从小方块指向大方块，写"外推"。
- 屏幕文字：大模型没法"试试看"
- 旁白：训练一个零点七B 的模型要八张卡跑十天，没法试错。好在语言模型有一个惊人的规律：loss 随算力的变化非常平滑，平滑到可以用几个便宜的小模型，提前算出大模型的结果。这套规律叫 scaling law，把它用在实验设计上，就是这一章的内容。

### S03 算账：C ≈ 6ND
- 画面：一层矩阵乘 y = Wx；前向箭头标"2N"，反向两支箭头标"对输入 2N""对权重 2N"；合计 6N。下方一根横条：主线每 token 的 FLOPs，6N 部分橙色、注意力部分紫色，标 40%。
- 屏幕文字：训练算力 C ≈ 6·N·D（N 参数，D token）
- 旁白：先学会算账。前向时，每个参数做一次乘加，是两次浮点运算；反向时，要对输入求一次梯度，再对权重求一次梯度，又是四次。所以训练一个 token 大约是六倍参数量，总算力就是六乘 N 乘 D。注意力里还有两个没有参数的矩阵乘，序列越长越贵：主线模型用四千长度训练时，它占了四成。我们用 PyTorch 的计数器实测过，公式和实测逐位一致。

### S04 loss 是算力的幂律
- 画面：log-log 坐标，横轴算力、纵轴 loss；五条曲线分别是 0.1B、0.3B、1B、3B、10B 模型（用 Epoch 复现系数计算），每条先降后平；它们的下包络线高亮成黄色"最优前沿"。
- 屏幕文字：L(N, D) = E + A/N^α + B/D^β
- 旁白：把不同大小的模型，喂不同量的数据，画在算力对 loss 的对数坐标上，就是这张图。每条线是一个固定大小的模型：一开始 loss 快速下降，然后被模型容量卡住，趴平了。所有曲线的下沿，是给定算力下能达到的最好结果。Chinchilla 用一个公式描述了它：一个常数，加上模型太小的代价，再加上数据太少的代价。

### S05 Chinchilla：每个参数约 20 个 token
- 画面：四条 IsoFLOP 抛物线（横轴模型大小、纵轴 loss），每条的谷底打一个点，谷底连成线；旁边写"约 20 token/参数"。
- 屏幕文字：算力最优：D ≈ 20·N
- 旁白：固定算力，在模型大小和数据量之间换来换去，loss 会画出一条抛物线，谷底就是最优分配。Chinchilla 发现：模型每大一倍，数据也该多一倍，大约每个参数二十个 token。更早的 Kaplan 让模型长得更快；后来的复现发现，差别主要来自小模型的超参没调好和算力口径不同。记住这一点，后面还会遇到。

### S06 为什么小模型要"过训练"
- 画面：横向对数柱状图：Chinchilla 20、本课主线 580、Puro-2B 700、Llama 3 8B 1,875、MobileLLM-R1 4,426、Qwen3-0.6B 60,000，20 处画一条虚线。
- 屏幕文字：token / 参数（对数坐标）
- 旁白：可现实里的小模型，几乎没人按二十来训。Qwen3 的零点六B 训了三十六万亿 token，是参数的六万倍。原因是 Chinchilla 只算训练的账，而模型训完要被用上亿次，每生成一个 token 又要两倍参数量的算力。模型越小，推理越便宜，那就多花点训练算力，把小模型训得更久。

### S07 过训练的价格
- 画面：左边小表：要服务的 token 数 0、1e12、1e13、1e14 → 最省总算力的模型 2.25B、0.84B、0.56B、0.44B；右边两个数：主线 loss 比同算力最优高 3.5%；同样的 loss，最优分配只要 40% 的算力。
- 屏幕文字：推理越多 → 模型越小、训得越久
- 旁白：用公开的 Chinchilla 系数算一笔账：如果模型一辈子要生成一万亿个 token，最划算的是零点八B 左右；一百万亿，就降到零点四B 左右。过训练也有价格：主线零点六九B、四千亿 token，loss 比同样算力下的最优分配高百分之三点五。这是明码标价的交易，我们为了端侧可用、和零点八B 的标杆同级比较，接受它。

### S08 先调参，再拟合
- 画面：右上角"极小配置演示"。左图：四条学习率 U 形曲线（横轴学习率对数、纵轴验证 loss），每条最低点打星；右图：最优学习率对参数量的对数直线，外推到留出尺寸。
- 屏幕文字：每个尺寸都要调学习率
- 旁白：现在自己做一遍。我们在 CPU 上训练四个小模型，从一万到二十万参数，每个扫五个以上的学习率。最优学习率随模型变大一路往下走，从零点零二降到零点零零二。如果偷懒，所有尺寸都用最小模型调出来的学习率，大模型反而比小模型还差，拟合出来的规律会告诉你"做大没用"。最新的研究正是这么说的：小模型对超参极其敏感，没调好的小实验会骗人。

### S09 迷你阶梯：拟合 L(N, D)
- 画面：右上角"极小配置演示"。对数横轴是 token 数，纵轴 loss；四种颜色的点是四个尺寸，每个尺寸 3–4 个预算；同色曲线是拟合的 L(N, D)。右侧：本次拟合的 α、β 与最大误差（现算），按尺寸 bootstrap 的 α 区间（现算），以及"课程构建机上：α≈0.52、β≈0.58"（写死的对照）。
- 屏幕文字：WSD 分叉：一次训练得到多个预算
- 旁白：每个尺寸只训练一条主干，学习率在稳定段不变；在不同位置分叉出去，各接一小段衰减，一次训练就得到三四个不同数据量的点。两个最小的模型还多训一个一百万字节的预算，让阶梯覆盖"过训练"区，因为主线模型就在那里。十四个点拟合出来，画面上 {α|阿尔法} 约零点九八，最大误差百分之二点四。可同一套实验，在写书的那台机器上，{α|阿尔法} 约零点五二。只是浮点运算顺序的一点差别，这个指数就差了将近一倍。按尺寸做 bootstrap，{α|阿尔法} 的区间几乎盖满了整个搜索范围：只有四个尺寸，模型又小，噪声不小；{α|阿尔法} 变大时，常数项跟着变大，曲线几乎一模一样。所以极小规模拟合出来的指数不能当真，要看下一步的留出检验。

### S10 外推检验
- 画面：右上角"极小配置演示"。留出尺寸 s5 的三个预算：灰色误差条是 95% 区间，黄色点是预测，绿色点是实际训练结果；每格上方标出误差（本机渲染 −1.02%、−0.15%、+1.51%）；右侧判定"N 个点落在区间外"（现算），下面一行"课程构建机上：3 个都在区间内"（写死的对照）。
- 屏幕文字：留出检验：大一号的模型，真的训出来对答案
- 旁白：关键一步是检验。我们用学习率的规律外推出一个大一倍多的模型该用的学习率，真的去训练它，再和预测对答案。三个预算上，误差分别是负一点零二、负零点一五、正一点五一个百分点，和拟合点自己的误差差不多大；但最短预算那个点，稍稍跑出了 bootstrap 的百分之九十五区间。在写书的那台机器上，三个点都在区间里。这个区间只算了换一组尺寸带来的不确定度，没算这次训练自己的噪声，所以偏窄。跑出区间的点要如实报告，这就是闸门一要做的事，只是缩小了几万倍。

### S11 真实世界：Delphi
- 画面：一条对数算力轴；左段 3e18 到 3e20 标"拟合"，右侧 1e21、1e22、1e23 三个留出点；上面一行"第一次：1e22 偏 2.5%、1e23 发散"（红），下面一行"修配方后：+0.5%、+0.2%、+0.2%"（绿）。
- 屏幕文字：外推 300 倍，误差 0.2%
- 旁白：大规模上也是这样吗？Marin 团队的 Delphi 用七个小预算拟合，外推到三百倍之外的一万亿亿亿次运算量，误差只有零点二个百分点。但他们第一次失败了：小预算上拟合得很漂亮，外推到一百倍时偏了两个半百分点，最大的那次直接发散。原因是学习率规则没有随训练长度下调。他们修的是配方，不是拟合曲线。

### S12 闸门 1：交给作者决定
- 画面：流程图：阶梯实验 → 验证 loss 外推（带区间）→ 软指标 → S 形映射 → 基准分数；另一支：后训练配方 → (a) 阶梯 Base、(b) 同尺寸开源 Base → 工具调用得分；汇合到"能否达到硬目标？是：开训；否：改配方或目标"。
- 屏幕文字：闸门 1 = 外推预测 + 配方验证
- 旁白：闸门一交给作者的报告有三件事。第一，外推主线模型的 loss，附上区间。第二，外推基准分数：小模型的准确率常常贴着随机水平，所以先对正确答案的概率这种连续指标做外推，再借公开模型把它换算成分数。第三，把后训练配方分别套在阶梯的小模型和一个现成的同尺寸开源模型上，看工具调用能到多少。预测达不到硬目标，就不开始烧钱。

### S13 主线决策
- 画面：左侧预算表：MFU 0.4 → 410B token、MFU 0.5 → 512B；"500B 需 $6,100"划红线；右侧两行结论：Muon 已达共识（Kimi K2、GLM-4.5、DeepSeek-V4），迷你阶梯上领先（右上角"极小配置演示"）；FP8 已达共识，但 zero 尚未实现、不计入预算。
- 屏幕文字：0.69B × 约 400B token（$5K 以内）
- 旁白：最后是主线的决策。五千美元按四成的硬件利用率，能买约四千一百亿 token，原计划的五千亿要六千一百美元，超线了。所以我们计划四千亿，用 WSD 调度，稳定段随时可以停，第二步实测吞吐以后再决定要不要训到五千亿。Muon 优化器已经被三家头部模型采用，在我们的小实验里也明显领先，阶梯里会和 AdamW 正面对比后再定；FP8 也是共识，但我们的代码还没实现，先不指望它省钱。

### S14 小结
- 画面：四个方块连成链：算账 6ND → 调参 → 拟合与留出检验 → 外推与决策；最后"下一章：数据"。
- 屏幕文字：先算账，再调参，再外推，最后才花钱
- 旁白：回顾一下：用六 N D 算账；每个尺寸先调好学习率；用阶梯拟合 loss，并留一个更大的模型检验外推；最后把预测和预算一起交给人来决定。阶梯实验固定了配方，而配方里最重要的一项是数据。下一章，我们准备主线模型的数据和分词器。

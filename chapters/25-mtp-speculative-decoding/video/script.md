## 二、分镜与旁白

### S01 片头
- 画面：标题卡"第 25 章 / 多 token 预测与推测解码"，副标题"让小模型先猜，大模型一次改完"。
- 屏幕文字：第 25 章 · 多 token 预测与推测解码
- 旁白：上一章的混合专家，让每个 token 只用一小部分参数。但不管模型怎么设计，生成的时候，还是一个 token 一个 token 地往外蹦。这一章我们来打破这个限制：让一个便宜的小模型先猜，大模型一次改完，而且输出的质量一点都不变。

### S02 decode 在等数据
- 画面：左边一排橙色方块，每块下面只出来一个 token；右边坐标系：横轴"一次喂几个 token"，纵轴"耗时（相对 1 个）"，实测点几乎平躺，对比一条"按计算量涨"的红线。
- 屏幕文字：喂 17 个只慢不到 2 倍（本机 CPU 实测）
- 旁白：先看为什么能做到。decode 阶段，模型每生成一个 token，都要把全部权重从显存里读一遍，却只做很少的计算，硬件大部分时间在等数据。所以一次多喂几个 token，几乎不多花时间。我们在 CPU 上测了第十章的小模型：一次喂十七个 token，计算量是十七倍，耗时却还不到两倍。检查一段话，比写一段话便宜得多。

### S03 草稿先猜，目标一次检查
- 画面：上排蓝色方块是草稿猜的 4 个字符；中排橙色框是目标模型一次前向在 4 个位置的答案；草稿上方逐个出现 ✓ ✓ ✗；下排绿色是本轮产出（2 个草稿 + 1 个纠正）。
- 屏幕文字：接受 2 个 + 目标自己的 1 个纠正 = 3 个 token，只跑了 1 次目标模型
- 旁白：这就是推测解码的思路。先让一个只有一层的草稿模型，自回归地猜四个字符。然后把它们一次性喂给目标模型，一次前向，得到每个位置上目标模型自己的答案。从左往右比：前两个一致，接受；第三个不一致，就停下，换成目标模型的答案。这一轮只跑了一次大模型，就产出了三个字符。

### S04 贪心逐字相同，拒绝要回滚
- 画面：左边代码（while 接受循环、seq += …、truncate 回滚）；右边一排 KV cache 方块，最后 3 个红色的淡出；下方"逐字相同 = 是"。
- 屏幕文字：贪心：输出逐字不变；拒绝后回滚缓存
- 旁白：贪心解码的时候，输出的每个字，要么是和目标一致的草稿，要么是目标自己的答案，所以结果和目标模型单独生成逐字相同。草稿只决定一次能走几步，不决定写什么。唯一要小心的是，被拒绝的草稿已经写进了 KV cache，必须回滚扔掉，否则后面的注意力会看到从没发生过的历史。我们在四段提示词、不同的 k 下对拍，全部逐字相同。

### S05 采样：按 min(1, p/q) 接受
- 画面：左边 6 个词的柱状图，橙色 p 和蓝色 q 并排；右边接受规则公式和两行说明；最后 α = Σ min(p, q) 和实测接受率。
- 屏幕文字：accept with prob. min(1, p(x)/q(x))
- 旁白：如果是随机采样呢？目标模型给出一个分布 {p|p}，草稿给出另一个分布 {q|q}。草稿按 q 抽出一个 token，以 p 除以 q 和 1 之间较小的那个概率接受它。p 大于等于 q 的 token，草稿给少了，一律接受；p 小于 q 的，草稿给多了，按比例拒绝一部分。平均接受的概率，就是 p 和 q 逐项取较小值再加起来，记作 {α|alpha}。

### S06 残差分布，结果恰好是 p
- 画面：蓝色 q 柱换成红色的残差 max(0, p − q)；右边推导公式 P(x) = min(p,q) + (1−α)·残差 = p(x)；然后绿色的"抽 20 万次的结果"和橙色 p 并排，几乎一样高；右下 TV 距离和卡方 p 值。
- 屏幕文字：P(x) = min(p,q) + (1−α)·max(0,p−q)/(1−α) = p(x)
- 旁白：被拒绝的时候，不是随便重抽，而是从残差分布里抽：p 减 q，负的部分截成零，再归一化。它正好补上了草稿给少了的那些 token。把接受和重抽两条路加起来，每个 token 的总概率恰好等于 p。我们抽了二十万次来验证：结果和 p 几乎完全重合，卡方检验通过；而直接用草稿的样本，就差得很远。

### S07 一轮能产出几个
- 画面：左边 5 行小方格，分别是"接受 0 个 → 产出 1 个"到"接受 4 个 → 产出 5 个"（绿 = 接受，红 = 纠正，黄 = 奖励）；右边逐行出现期望产出和加速比公式。
- 屏幕文字：E = (1 − α^{k+1})/(1 − α)　加速比 = E / (1 + kc)
- 旁白：一轮里，第一个产出的 token 一定有；第二个，要第一个草稿被接受；第三个，要前两个都被接受。所以每轮平均产出一加 α，加 α 的平方，一直加到 α 的 k 次方。每轮的代价，是一次大模型加上 k 次草稿，c 是草稿一步和大模型一步的时间比。两者一除，就是加速比。

### S08 加速比曲线
- 画面：横轴 α（0.3–0.97），纵轴加速比；c = 0.05 时 k = 1、3、6 三条曲线；右侧两行说明。
- 屏幕文字：α 低：猜多了白费草稿的算力　α 高：值得多猜几个
- 旁白：把公式画出来：α 越高，加速越多；草稿越便宜，越值得多猜几个。但 α 低的时候，k 等于六的曲线反而掉到了 k 等于三的下面：猜得太多，只是白白浪费草稿的算力。所以 k 要按 α 和 c 来选，不是越大越好。

### S09 小实验
- 画面：右上角"极小规模实验"标注；表格：k = 1、3、6 时的接受率、目标前向次数（原来 800）、每次前向产出；下方 k = 3 的 CPU 时间与加速倍数，以及一行灰字解释。
- 屏幕文字：k = 3：目标前向 800 → 306 次
- 旁白：在我们的小实验里，接受率大约是零点七，k 等于三的时候，目标模型的前向次数从八百次降到三百零六次。但在 CPU 上，实际只快了两成左右：这个一层的草稿，因为每个算子都有固定开销，一步要花目标的五分之一左右；验证四个位置，也比生成一个慢了三成。真实的 GPU 系统里，草稿通常小两个数量级，论文里的实测加速是两到三倍。

### S10 草稿从哪来
- 画面：三张卡片：同家族的小模型 / 提示词查找 / 模型自带的草稿头 MTP；下方黄字。
- 屏幕文字：无论草稿是谁，输出分布都不变；草稿只影响快慢
- 旁白：草稿从哪来？推测解码对草稿没有任何正确性要求，只要和目标用同一个分词器。可以是同家族的小模型，最好再用大模型的输出蒸馏一下；可以是提示词查找，直接从上下文里复制，几乎不花时间；也可以让模型自己长出一个草稿头，它能读到大模型的隐藏状态，猜得最准。

### S11 DeepSeek-V3 的 MTP 模块
- 画面：自下而上的结构图：主模型输出表示 h_i，Emb(t_{i+1}) 从共享 embedding 来；各过一个 RMSNorm；拼接 → 线性投影 2d→d → 一个 Transformer block → 共享输出头 → 预测 t_{i+2}；右下角损失公式和 λ。
- 屏幕文字：L = L_main + λ · L_MTP
- 旁白：最主流的草稿头，是 DeepSeek V3 的多 token 预测，MTP。主模型在位置 i 的表示，和下一个 token 的 embedding，各过一个 RMSNorm，拼起来投影回原来的宽度，再过一个 Transformer block，用和主模型共享的输出头，预测再下一个 token。训练时，把它的损失乘上 {λ|lambda}，加到主损失上。推理时，可以直接丢掉它，也可以拿它当草稿。

### S12 MTP 小实验
- 画面：右上角"极小规模实验"标注；表格：不加 / 加 MTP 的验证 loss、下一个字符准确率、MTP 下下个字符准确率；下方三行：自推测接受率与前向次数、逐字相同、DeepSeek-V3 的 85%–90% 与 1.8 倍。
- 屏幕文字：拿 MTP 当草稿做自推测
- 旁白：我们给第十章的小模型加了一个 MTP 模块，用同样的初始化和数据训练六百步。MTP 模块预测下下个字符的准确率，和主模型预测下一个字符差不多高，因为它看得到下一个字符是什么。把它当草稿，主模型的前向次数少了四成多，输出和主模型逐字相同。DeepSeek V3 报告，第二个 token 的接受率在百分之八十五到九十，解码速度提到约一点八倍。

### S13 谁在用
- 画面：表格：DeepSeek、千问、智谱 GLM、MiniMax 与小米 MiMo、NVIDIA 与 Google；最下面一行黄字：vLLM、SGLang 内置推测解码。
- 屏幕文字：MTP：多家主力模型采用
- 旁白：MTP 已经是共识：DeepSeek 的 V3 和 V4，千问的 Qwen3-Next 和 Qwen3.5，智谱的 GLM 4.5 和 GLM 5，MiniMax M2，小米 MiMo，英伟达的 Nemotron 3 Super，都带着 MTP 层；Google 也给 Gemma 4 发布了专门的草稿模型。推理引擎 vLLM 和 SGLang，都内置了推测解码。

### S14 从极简到生产级 + 下一章
- 画面：左边两个生产级文件和它们做了什么；右边主线模型的计划；最后出现"下一章：当前最先进开源模型全景"。
- 屏幕文字：主线模型不加 MTP；第二步另训小草稿，在 GPU 上实测
- 旁白：生产级代码里，speculative 点 py 用预分配的 KV cache 做回滚，支持 top p 和提示词查找；mtp 点 py 实现了 DeepSeek 式的 MTP 模块和自推测解码，测试保证贪心逐字相同、采样分布不变。我们的主线模型不加 MTP，不冒架构风险；第二步可以给它另训一个同分词器的小草稿，再到 GPU 上实测加速。下一章，我们把整个第五部分拼回真实的模型：当前最先进开源模型的全景。

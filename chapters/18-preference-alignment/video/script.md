## 二、分镜与旁白

### S01 片头
- 画面：标题卡"第 18 章 / 偏好对齐"，副标题"从 RLHF 到 DPO"。
- 屏幕文字：第 18 章 · 偏好对齐
- 旁白：上一章，我们用蒸馏让小模型学会了调用工具。可它还只是在模仿：示范怎么写，它就怎么写。这一章要解决的问题是，怎么让模型学会"哪种回答更好"。

### S02 判断比写容易
- 画面：一个提示词，下面两个回答 A、B 并排；A 旁边出现绿色对勾"更好"。
- 屏幕文字：写出最好的答案很难；判断两个答案哪个好，容易得多
- 旁白：让人写一首好诗很难，但读两首诗，说出哪首更好，谁都会。偏好对齐就利用这一点：不再要求标注员写出完美答案，只让他在两个回答里挑一个。挑中的叫 chosen，落选的叫 rejected。标注员可以是人，也可以是一个更强的模型当裁判。

### S03 Bradley–Terry：分数差变成概率
- 画面：左边 S 形曲线 σ(Δ)，横轴"r(a) − r(b)"，纵轴"P(a ≻ b)"；Δ = 1、2 处标点 0.73、0.88。右边公式。
- 屏幕文字：P(a ≻ b) = σ(r(a) − r(b))
- 旁白：我们假设每个回答心里都有一个分数 r，谁的分数高，谁就更可能被选中。具体地说，a 赢的概率，等于两者分数差过一个 {sigmoid|西格莫伊德} 函数。分数差是一，概率零点七三；差二，零点八八。注意，只有差值进公式，所有分数同时加一百，概率不变。这叫 {Bradley–Terry|布拉德利 特里} 模型。

### S04 奖励模型：一个二分类
- 画面：公式 −log σ(r_w − r_l) 出现，旁边标注"标签恒为 1 的二分类交叉熵"；右侧小表：真实系数 1.5 / 0.4 与学到的 1.49 / 0.45。
- 屏幕文字：奖励模型损失 = −log σ(r_w − r_l)
- 旁白：有了这个模型，训练奖励模型就是最大化"chosen 赢"的对数概率。它其实就是第五章的二分类交叉熵，只不过 {logit|逻辑值} 换成了两个分数的差。玩具实验里，标注员按一点五倍质量加零点四倍长度打分，奖励模型学到了一点四九和零点四五。它学会了标注员的偏好，也学会了标注员的偏见：喜欢长回答。

### S05 RLHF 的目标：奖励减去 KL
- 画面：左边 π_ref 的 8 根灰色柱，右边策略 π 的柱子；中间一根"缰绳"连着两者；公式 E[r] − β·KL(π‖π_ref)。
- 屏幕文字：max E[r] − β·KL(π ‖ π_ref)
- 旁白：有了奖励模型，就可以让策略去追高分。但不能放任它追：奖励模型只在见过的回答附近靠谱。所以目标里还要减去 {β|贝塔} 乘以 KL 散度，也就是新策略离 SFT 模型有多远。你可以把 KL 想成一根缰绳，{β|贝塔} 就是缰绳的松紧。

### S06 缰绳太松：reward hacking
- 画面：横轴 β（对数），两条线：奖励模型分（橙）一路上升，真实质量（绿）先升后降；β = 0.03 处标"全押注水 900 字"。
- 屏幕文字：β 太小 → 代理分更高，真实质量反而下降
- 旁白：我们在 8 个候选回答上算出不同 {β|贝塔} 下的最优策略。缰绳很紧时，策略几乎不动，真实质量零点三五。放松到零点五，真实质量升到一点一二，最高。再松下去，奖励模型的分数还在涨，真实质量却掉到负零点五：策略把全部概率押在一个 900 字的注水回答上。奖励模型没见过这么长的回答，却给了它最高分。这就是 reward hacking。

### S07 PPO：用采样一步步摸过去
- 画面：流程图：采样 → 打分减 KL → 优势 = 奖励 − 价值 → 裁剪比例 → 更新；右边目标值曲线逼近闭式解的虚线。
- 屏幕文字：PPO：采样、价值基线、裁剪 ρ 到 [1−ε, 1+ε]
- 旁白：InstructGPT 用 PPO 解这个目标：从当前策略采样回答，奖励模型打分，再减去 KL 惩罚；用一个价值基线算优势；把新旧策略的概率比裁剪在一个小范围里，防止一步走太远。InstructGPT 的结果很有名：十三亿参数的模型，比一千七百五十亿的 GPT-3 更受标注员青睐。我们的玩具上，PPO 四百轮后和最优解几乎重合。PPO 这里只作铺垫，第十九章还会用到它。

### S08 最优解有闭式
- 画面：推导逐行出现：第一行目标，第二行 = β log Z − β KL(π‖π*)，第三行 π* = π_ref·exp(r/β)/Z，高亮。
- 屏幕文字：π*(y) = π_ref(y)·exp(r(y)/β) / Z
- 旁白：可是，PPO 花那么大力气采样摸索的最优策略，其实能直接写出来。把目标整理一下，它等于一个常数，减去 {β|贝塔} 倍的"当前策略到 π 星的 KL"。KL 永远不小于零，所以最优策略就是 π 星：参考模型的概率，乘以奖励的指数，再归一化。奖励高的回答，概率被放大；{β|贝塔} 越大，放大得越温和。

### S09 反解奖励，Z 消掉
- 画面：接上一镜：π* 的式子取对数反解出 r = β log(π*/π_ref) + β log Z；代入 σ(r_w − r_l)，两个 β log Z 相互抵消（划掉动画）；最后得到 DPO 损失，框起来。
- 屏幕文字：L_DPO = −log σ(β[(log π(y_w) − log π_ref(y_w)) − (log π(y_l) − log π_ref(y_l))])
- 旁白：把这个式子反过来读：奖励等于 {β|贝塔} 乘以策略和参考模型的对数概率比，再加一个常数 {β|贝塔} log Z。Z 很难算，但没关系，把它代进 {Bradley–Terry|布拉德利 特里}，只有奖励的差进公式，常数正好消掉。于是奖励模型不见了，剩下一个只含策略和参考模型的损失。这就是 DPO，直接偏好优化：你的语言模型，本身就是一个奖励模型。

### S10 梯度在做什么
- 画面：两根柱子 log π(chosen)（绿）与 log π(rejected)（红）；箭头一上一下；右边 σ(−h) 曲线，h < 0 处箭头粗，h > 0 处箭头细。
- 屏幕文字：梯度 ∝ β·σ(−h)：排错了用力推，排对了轻轻推
- 旁白：DPO 的梯度很好懂：抬高 chosen 的概率，压低 rejected 的概率。力度是 {β|贝塔} 乘以 {sigmoid|西格莫伊德} 负 h，h 是隐式奖励的差。如果模型现在把 rejected 排在前面，h 是负的，推得最用力；已经排对了很多，就几乎不推。错多少，改多少。

### S11 在小模型上跑一次
- 画面：左边训练曲线 margin 与 acc 随步数上升；右边两根柱子 log π(chosen)、log π(rejected) 随步数移动（数值从代码读取）；底部"留出答对概率 0.37 → 0.43"（渲染机现算，本机画面 0.368 → 0.430）。
- 屏幕文字：玩具任务：a+b=？ SFT 示范只有 40% 是对的
- 旁白：我们在一个两万参数的小模型上试试。它做过 SFT，但示范里只有百分之四十是对的，所以它也学会了经常答错。拿二百八十对"正确答案胜过错误答案"的偏好数据做 DPO，一百五十步后，margin 从零涨到零点六，排序准确率零点九五。rejected 的对数概率从负三点四掉到负八点九，chosen 从负一点零四升到负零点五五。在训练时没见过的三十道题上，答对的概率从零点三七升到零点四三。

### S12 三个坑
- 画面：三栏：①学习率表（1e-4、1e-3、1e-2、5e-2 对应格式正确率条形，下方“lr=1e-2：margin 4.20，格式 0.62”，渲染机现算）；②chosen 与 rejected 的曲线一起下降；③右上角带"极小配置演示"标注的冒烟测试说明：5e-4 → 格式 0.16 → 0，改 5e-5。
- 屏幕文字：lr 太大会坏格式；chosen 也可能一起掉；margin 高 ≠ 模型好
- 旁白：DPO 也有坑。第一，学习率。调到一乘十的负二次方，margin 冲到四以上，看起来很漂亮，可采样出来的回答将近四成连格式都不对；换一台机器重跑，甚至超过一半。margin 高，不等于模型好。我们主线的冒烟测试就踩过：学习率五乘十的负四次方，后面强化学习阶段的格式正确率从零点一六掉到零，换成五乘十的负五次方才稳住。第二，chosen 的概率也可能一起掉：当错答案和对答案只差一点点时，损失在降，chosen 的概率却一路下滑，留出题反而变差。第三，只看训练集的 margin 会高估效果，一定要看留出集。

### S13 从极简到生产级
- 画面：左边极简版五行 DPO 损失；右边 zero/post/dpo.py 的结构：encode_pair（只算回复）→ batch_logps（chosen、rejected 拼成一批）→ 参考 log 概率预先算好 → dpo_loss；右上角"极小配置演示"标注，显示 loss 0.693 → 0.526、acc 0.75、margin 0.39、24 步。
- 屏幕文字：zero/post/dpo.py：只算回复 token、一批前向、参考模型预先算好
- 旁白：主线代码做的是同一件事，多了几样工程：只对回复部分求对数概率，提示词不算；chosen 和 rejected 拼成一个批次一次前向；参考模型的对数概率在训练前算好存起来，省下一份模型的显存。极小配置的冒烟测试跑了二十四步，损失从零点六九三降到零点五二六，排序准确率零点七五。主线模型的 DPO 要等 GPU 训练后再补。

### S14 谁在用，下一章
- 画面：一排家族标签：Llama 3、Qwen2 / 2.5、DeepSeek LLM、Tülu 3 / OLMo 2、Nemotron-4、SmolLM3（APO）；最后出现"下一章：强化学习"。
- 屏幕文字：DPO：Llama 3、Qwen2/2.5、DeepSeek LLM、OLMo 2、Nemotron-4、SmolLM3
- 旁白：DPO 简单、稳定、不用采样，Llama 3、千问二和二点五、DeepSeek LLM、OLMo 2、Nemotron 都在后训练里用了它，SmolLM3 用的是它的一个变体。但偏好对只能告诉模型"哪个更好"。像工具调用这种对错能自动判定的任务，还可以让模型自己去试、自己拿分数。下一章，我们讲强化学习：GRPO 和可验证奖励。

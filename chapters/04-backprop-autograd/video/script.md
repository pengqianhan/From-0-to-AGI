## 二、分镜与旁白

### S01 片头
- 画面：章节标题卡淡入："第 4 章 / 反向传播与自动微分 / From 0 to AGI"，副标题"让计算机替你求导"。
- 屏幕文字：第 4 章 · 反向传播与自动微分
- 旁白：欢迎回来。前三章，每一个梯度公式都是我们用笔推出来的。这一章，我们要写一个大约一百五十行的小引擎，让计算机自动求出任意网络的梯度。PyTorch 里那句 loss 点 backward，背后就是这件事。

### S02 手推梯度的痛
- 画面：左边第 1 章的两个梯度公式（短），中间第 3 章两层网络对第一层权重的梯度（长），右边一个"再加一层？"的红色问号。
- 屏幕文字：手推梯度：模型每变一次，就要重推一次
- 旁白：回忆一下。第一章的直线只有两个参数，梯度公式一行就写完了。到了第三章的两层网络，第一层权重的梯度要穿过激活函数、穿过第二层权重，公式已经很长。再加一层，换一个激活函数，换一个损失，全都得重推，而且推错了很难发现。大模型有几十亿个参数、几百种运算，手推是不可能的。我们需要一个办法，让计算机自己把梯度算出来。

### S03 链式法则
- 画面：三个方块 x → u → y，边上写"× 3"和"× 12"；一个小变化从 x 传到 y 被放大 36 倍；下方写出链式法则公式。
- 屏幕文字：dy/dx = dy/du · du/dx
- 旁白：这个办法的数学基础只有一条：链式法则。想象一组齿轮。u 等于三倍的 x，x 转一点，u 转三倍；y 等于 u 的平方，在 x 等于 2、u 等于 6 的地方，u 转一点，y 转十二倍。那么 x 转一点，y 就转三乘十二，也就是三十六倍。复合函数的导数，就是沿路每一段的局部导数相乘。每一段只需要知道自己那一小步。

### S04 计算图：前向
- 画面：计算图从左到右：叶子 a=2、b=−3、c=10（橙色参数），运算节点 ×、+、²；数值沿边向右流动：d=−6、e=4、L=16。
- 屏幕文字：前向：算数值，顺便记下"谁由谁算出来"
- 旁白：把一个式子拆成最小的运算，画成一张图，就叫计算图。比如 L 等于 a 乘 b 加 c 的平方。前向的时候，数值从左往右流：a 乘 b 得到负六，加上 c 得到四，平方得到十六。关键在于，每做一次运算，我们都记下一个节点：它的值是多少，它由哪几个节点、用什么运算算出来。算完一遍，整张图就记录下来了。

### S05 反向传播：梯度往回流
- 画面：从 L 出发，红色梯度沿边向左流：∂L/∂L = 1 → ∂L/∂e = 8 → ∂L/∂d = 8、∂L/∂c = 8 → ∂L/∂a = −24、∂L/∂b = 16；每条边上标出局部导数。
- 屏幕文字：反向：上游梯度 × 局部导数
- 旁白：反向的时候，梯度从右往左流。起点是 L 对自己的导数，等于一。平方节点的局部导数是二乘 e，也就是八，所以 L 对 e 的梯度是八。加法节点的局部导数是一，它把八原样分给 d 和 c。乘法节点的局部导数是另一个输入：传给 a 的是八乘 b，负二十四；传给 b 的是八乘 a，十六。每一步都是同一个动作：上游传来的梯度，乘以本节点的局部导数。

### S06 每种运算只写一次
- 画面：左边一张小表：运算 → 局部导数（+、×、幂、tanh、exp）；右边是 `__mul__` 的代码，`_backward` 两行被高亮。
- 屏幕文字：每种运算：前向一行 + 局部导数一行
- 旁白：这就是自动微分的秘密：每种运算的局部导数只需要写一次。加法、乘法、幂、{tanh|tan h}、指数、对数，每一种都是前向算数值，再配一个小函数，负责把梯度乘上局部导数、传给输入。不管网络多深、多复杂，都是这几种运算拼出来的，梯度自然也就能拼出来。

### S07 分叉：梯度要相加
- 画面：y = x·x + x 的计算图，x 有三条出边；三条红色梯度 3、3、1 流回 x 并相加成 7；下方代码 `self.grad += ...` 中的 `+=` 高亮。
- 屏幕文字：一个节点被用了几次，梯度就从几条路流回来 → 相加
- 旁白：还有一个细节。如果一个节点被用了不止一次，比如 y 等于 x 乘 x 再加 x，x 就有三条路通向 y。反向时，三条路各自带回一份梯度：三、三和一。正确答案是把它们加起来，等于七，也就是二 x 加一。所以代码里写的是加等于，而不是等于。我们故意把它改成等于，梯度检验的相对误差立刻变成零点九七，完全错了。这也是 PyTorch 每一步要先清零梯度的原因：梯度默认就是累加的。

### S08 拓扑排序：谁先谁后
- 画面：计算图的节点按拓扑序排成一行并编号；反向时从最后一个编号往前依次点亮。
- 屏幕文字：按拓扑序的逆序反向：先收齐梯度，再往上游传
- 旁白：那反向的时候，先处理哪个节点？规则是：一个节点必须先收齐所有下游传回来的梯度，才能继续往上游传。做法是先做一次拓扑排序，保证每个节点都排在用到它的节点前面，然后倒过来走一遍。整个 backward 函数就这么几行：排序，把起点的梯度设为一，逆序调用每个节点的小函数。

### S09 梯度检验
- 画面：两列数字并排：autograd 的梯度 vs 数值梯度（中心差分），逐位相同；下方显示误差：正确引擎约 10⁻¹⁰，改成等于后 0.97。
- 屏幕文字：数值梯度 (L(p+ε) − L(p−ε)) / 2ε
- 旁白：怎么知道引擎算得对？用第一章任务二的老办法：梯度检验。把某个参数往上挪一点点，再往下挪一点点，看损失变了多少，就得到一个数值梯度。我们拿一个用到全部运算的表达式，再拿一个九十七个参数的小网络来检验，autograd 和数值梯度的相对误差都在十的负十次方左右。换成有 bug 的版本，误差接近一，一眼就能看出来。

### S10 用它训练 MLP
- 画面：左边坐标系里是 sin(x) 的 20 个蓝点，绿色拟合曲线随训练步数变化；右边显示训练循环代码和损失数字从 0.716 降到 0.0094。
- 屏幕文字：MLP(1, [8, 8, 1])：97 个参数，没有一行手推梯度
- 旁白：现在用它训练一个真正的网络：输入一个数，两个八个神经元的隐藏层，激活函数是 {tanh|tan h}，一共九十七个参数，去拟合正弦曲线上的二十个点。训练循环和第一章一模一样：前向算损失，清零梯度，调用 backward，参数减去学习率乘梯度。五百步之后，损失从零点七二降到零点零零九四。整个过程中，我们没有手推任何一个梯度。

### S11 代价：标量图很慢
- 画面：一次前向记录 3720 个节点（一堆小点）；右边对比表：20 个样本 Value 44 ms vs PyTorch 0.36 ms；200 个样本 775 ms vs 0.41 ms；最后出现 Y = XW 与 ∂L/∂X = G·Wᵀ。
- 屏幕文字：标量图：每个数一个节点；张量图：一次矩阵乘法一个节点
- 旁白：但它很慢。二十个样本前向一次，就记录了三千七百多个节点，每个节点都是一个 Python 对象。在我们的机器上一次实测，前向加反向要四十多毫秒，PyTorch 只要零点几毫秒；样本增加到两百个，我们的引擎要七百多毫秒，PyTorch 几乎没变。区别在于，真实框架的节点是整个张量：一次矩阵乘法就是一个节点，它的反向也是矩阵乘法，比如 Y 等于 X 乘 W，传给 X 的梯度就是上游梯度乘以 W 的转置。这叫向量雅可比积，原理和我们的标量引擎完全一样。

### S12 从极简到生产级：PyTorch 对拍
- 画面：左边 Value 引擎，右边 PyTorch nn.Sequential；中间逐个参数打勾 allclose；显示最大差 8.3×10⁻¹⁷、500 步后损失都是 0.0093662407、gradcheck 通过。
- 屏幕文字：同一个 MLP：Value 引擎 vs torch.autograd
- 旁白：最后和 PyTorch 对拍。把同样的初始权重拷进 PyTorch，算同一个损失，九十七个参数的梯度全部一致，最大差别在十的负十七次方，是双精度浮点的舍入误差。两边各训练五百步，最终损失小数点后十位都一样。PyTorch 也自带梯度检验工具 gradcheck，用的正是我们刚才的数值梯度办法。

### S13 小结与下一章
- 画面：四条要点依次出现：前向记图、逆拓扑序反向、上游梯度乘局部导数、分叉处相加；最后出现"下一章：分类与概率"。
- 屏幕文字：前向记图 → 逆序反向 → 乘局部导数 → 分叉相加
- 旁白：总结一下。前向时记录计算图；反向时按拓扑序的逆序走一遍；每个节点把上游梯度乘上局部导数，传给输入；一个节点被用了几次，梯度就加几次。有了自动微分，网络想加多深都行。下一章，我们让网络做分类，那时候均方误差就不够用了，我们需要概率和交叉熵。

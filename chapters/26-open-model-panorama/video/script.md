## 二、分镜与旁白

### S01 片头
- 画面：章节标题卡："第 26 章 / 当前最先进开源模型全景"。
- 屏幕文字：第 26 章 · 当前最先进开源模型全景
- 旁白：这是整门课的最后一章。第五部分的零件，KV cache、滑动窗口、线性注意力、MoE、MTP，我们都拆过了。现在把它们装回真实的模型里：2026 年 9 月，最强的开源模型到底长什么样？

### S02 先确认"最新"是谁
- 画面：六张卡片依次出现：DeepSeek-V4-Pro、Qwen3.8-2.4T、Kimi-K3、gpt-oss-120b、GLM-5.3、MiniMax-M3，每张写总参数 / 激活参数；前四张标"拆解"。
- 屏幕文字：2026-09 各家最新旗舰（读自 Hugging Face）
- 旁白：名单变得太快，凭记忆一定会错。所以我们直接在 Hugging Face 上，按时间列出每家机构的仓库，找到最新的旗舰：DeepSeek V4 Pro、千问 3.8、Kimi K3、gpt-oss、GLM 5.3，还有 MiniMax M3。最大的有两万八千亿参数，每个 token 只用到其中一千多亿。下面画面里的每个数字，都从它们的配置文件和模型卡里读出来。

### S03 树根与主干
- 画面：左边出现 GPT-2 节点，向右长出"现代稠密块"，稠密块里列出 RMSNorm、RoPE、SwiGLU、GQA、QK-Norm、共享 embedding；旁边标"主线模型 = 这根主干"。
- 屏幕文字：GPT-2 → 现代稠密块（第 9 章）
- 旁白：先画一棵树。树根是 2019 年的 {GPT-2|G P T 2}。第九章我们把它换成了现代稠密块：前置的 {RMSNorm|R M S Norm}、{RoPE|rope} 位置编码、{SwiGLU|swish G L U}、{GQA|G Q A}、{QK-Norm|Q K norm}。这些零件，第六章到第十章一个一个讲过。六个最新旗舰全部还长在这根主干上，没有一家换掉它。我们的主线模型，就是这根主干本身，和千问 3 的 0.6B 同一个形状。

### S04 分枝一：MoE
- 画面：从主干长出"MoE：细粒度 + 共享专家"，再长出"无辅助损失均衡"（绿框）和"Latent MoE"（灰色虚线框，前沿）。
- 屏幕文字：MoE：6 家全用
- 旁白：从主干长出的第一根枝，是第二十四章的混合专家。六个旗舰没有一个例外，全是 {MoE|M o E}，五家带共享专家，四家用无辅助损失的偏置均衡。它省的是每个 token 的算力，代价是显存要装下全部专家。Kimi K3 走得最远：896 个专家选 16 个，而且专家在一个缩小的潜空间里算，不然总参数会翻一倍。

### S05 分枝二：每个位置少存点
- 画面：从 GQA 长出 MLA（绿框），再长出 CSA/HCA（灰色虚线框）；旁边标 DeepSeek 的 V2 → V4。
- 屏幕文字：GQA → MLA → 压缩注意力
- 旁白：第二根枝是压 KV cache。{GQA|G Q A} 少存头，{MLA|M L A} 把 K 和 V 压成一个潜向量。有意思的是，发明 {MLA|M L A} 的 DeepSeek，在 V4 里把它换掉了：每 4 个或 128 个 token 压成一条，K 和 V 共用，再配一个只看最近 128 个 token 的窗口。算下来，它的 KV cache 只有 V3.2 的一成左右。

### S06 分枝三、四：只看一部分，或者干脆不存
- 画面：滑动窗口 → 稀疏注意力（黄框，"2026 新晋"）；混合线性注意力 → KDA（灰虚线）。
- 屏幕文字：稀疏注意力：DeepSeek · GLM · MiniMax
- 旁白：第三根枝是只看一部分：滑动窗口按位置挑，稀疏注意力按内容挑。今年 MiniMax M3 也加入了，稀疏注意力刚好凑满三家，但三家挑法各不相同。第四根枝更彻底：大部分层换成线性注意力，根本不存 K 和 V。千问和 Kimi 都是大约三层线性配一层全注意力。

### S07 分枝五、六
- 画面：MTP（绿框）；残差流改造 mHC / AttnRes（灰虚线）；整棵树完整呈现，图例：绿 = 共识、黄 = 新晋、灰虚线 = 前沿。
- 屏幕文字：绿 共识 · 黄 新晋 · 灰 前沿观察
- 旁白：第五根枝是第二十五章的 {MTP|M T P}，四个旗舰在用，训练时多预测一个 token，推理时当草稿。第六根枝是 2026 年才冒出来的：DeepSeek 和 Kimi 开始改造残差连接本身，各走各的路，还只是前沿。整棵树里，绿色是共识，黄色是今年刚满三家的新晋共识，灰色的虚线框，是还在分化的地方。你会发现，每一根枝都在回答同一个问题：怎样更大、更长、更便宜。

### S08 逐层拆开：层的颜色
- 画面：8 行横条，每行一个模型，每一小格是一层，按层类型上色（蓝 全注意力、青 滑动窗口、绿 线性、紫 MLA、橙 CSA、红 HCA、黄 块稀疏）；主线模型在最下面一行。
- 屏幕文字：每一格是一层
- 旁白：把每个模型的层按类型涂上颜色，差别一眼就能看出来。gpt-oss 一层滑动窗口一层全注意力；千问和 Kimi 是三格绿色夹一格；DeepSeek V4 是两种压缩注意力交替；GLM 全部是 {MLA|M L A}；MiniMax 除了前三层都是稀疏。最下面是我们的主线模型：28 格，全是普通的全注意力。六个旗舰，没有一个是这样。

### S09 参数：总参数和激活参数
- 画面：对数刻度横条：每个模型两根，浅色是总参数、深色是激活参数；主线模型一根（稠密）。
- 屏幕文字：总参数 vs 激活参数（对数刻度）
- 旁白：再看参数。浅色是总参数，深色是每个 token 真正用到的激活参数。Kimi K3 两万八千亿，只激活一千零四十亿；gpt-oss 一千一百七十亿，只激活五十一亿。我们不下载权重，把配置交给 Hugging Face 官方的模型类，在一个不分配内存的设备上建模型再数参数，总参数都和模型卡对得上。只是各家算激活参数的口径不同，有的算上词表，有的不算。

### S10 KV cache：和参数量脱钩了
- 画面：128K 的 KV cache 横条（GiB，线性刻度）：六个旗舰 + Qwen3.5-0.8B；主线模型用 32K 的数值单独一条（标"32K"）。
- 屏幕文字：128K 上下文的 KV cache（BF16）
- 旁白：最有意思的是 KV cache。128K 上下文，1.6 万亿参数的 DeepSeek V4 不到 1 GiB，Kimi K3 是 3.4 GiB，而我们 7 亿参数的主线模型，只用 32K 就要 3.5 GiB。KV cache 已经和参数量脱钩了：决定它的，是有几层要存、每个位置存多少。这正是第五部分讲的全部内容。

### S11 共识与分化
- 画面：左栏"已成共识"（RMSNorm、GLU、MoE 6/6，RoPE 5/6，共享专家 5/6，MTP 4/6……），右栏"长上下文三派"（混合线性、稀疏、少存），下方"前沿"（压缩注意力、mHC、Latent MoE、NoPE）。
- 屏幕文字：按"至少 3 家"判定
- 旁白：按我们的规则，至少三个独立的家族在用才算共识。稳如磐石的是主干：{RMSNorm|R M S Norm}、门控前馈层和 {MoE|M o E} 六家全用，{RoPE|rope} 五家，{MTP|M T P} 四家。长上下文则分成了三派：混合线性注意力、稀疏注意力、少存压缩，每派都过了三家的门槛，但具体做法还在分化。压缩注意力、残差流改造，还只有一两家。

### S12 为什么主线模型只用主干
- 画面：主线模型的层条；右边四项旗舰技术（MoE、MLA、稀疏、混合线性）逐一打上"现在不用"及一句理由。
- 屏幕文字：主线模型：只用稠密共识块（GOAL 3.3）
- 旁白：那我们的主线模型为什么这么朴素？因为它只有七亿参数，上下文三万两千。{MoE|M o E} 是用显存换算力，小模型不划算；{MLA|M L A} 只出现在大模型里，还和 {QK-Norm|Q K norm} 不兼容；稀疏注意力省的是十万 token 以上的算力。更根本的是，在这个规模上，架构带来的差异远小于数据和后训练。我们把风险留给数据，架构选最稳的。

### S13 下一版加什么
- 画面：三根横条：32K 的 KV cache，现在 3.50 GiB、3:1 局部-全局 1.20 GiB、3:1 混合线性 896 MiB；旁边写"先加 MTP，再试 3:1 混合"。
- 屏幕文字：主线"下一版"：32K 的 KV cache
- 旁白：等第二步有了真实的基线，下一版最值得试两件事。一是一层 {MTP|M T P}，代价小，推理时能当草稿。二是三比一的混合线性注意力，和千问 3.5 的 0.8B 同一条路，32K 的 KV cache 从 3.5 GiB 降到九百兆左右。但它记性差一些，工具调用恰恰要精确复制参数名，所以必须先在同样算力下做对比实验，再决定。

### S14 回到起点
- 画面：一条路线从左到右：y = ax + b → 神经网络 → 注意力 → 现代 Transformer → 训练 → 后训练 → 架构演进 → 今天的旗舰；最后出现"第二步：在 GPU 上训练主线模型"。
- 屏幕文字：从 y = ax + b 到最先进的开源模型
- 旁白：回头看，第一章我们说，训练一个大模型，和拟合一条直线在结构上一模一样。现在可以补上数字了：两万八千亿个参数，每一步做的仍然是算损失、求梯度、沿着梯度的反方向走一小步。从一条直线，到一棵长满分枝的树，中间的每一步，都是上一步遇到的问题逼出来的。课程到这里就讲完了。接下来是第二步：在 {GPU|G P U} 上，真正把我们的主线模型训练出来。

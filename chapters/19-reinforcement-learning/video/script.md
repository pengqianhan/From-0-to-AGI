## 二、分镜与旁白

### S01 片头
- 画面：章节标题卡。
- 屏幕文字：第 19 章 · 强化学习
- 旁白：前面几章，模型学到的一切都来自别人给的答案：抄示范，抄老师，抄人类的偏好。这一章换一种学法：让模型自己去试，用一个能自动判对错的程序给它打分。这就是强化学习，也是我们主线模型的最后一个训练阶段。

### S02 模仿的天花板
- 画面：左边一个"老师"卡片，列出 7+5 → 2 的错误；右边柱状图：老师 0.684、SFT 采样 0.68、SFT 贪心 0.60、进位题 0.11。
- 屏幕文字：模仿学习的上限 = 示范数据
- 旁白：先看一个小实验。任务是两个个位数相加。老师不太会进位，进位的题有七成忘了写进位，比如七加五写成二。学生照着老师的示范学，结果采样准确率零点六八，和老师几乎一样；进位题上，贪心解码只剩零点一一。学生学得很认真，连老师的错误也一起学会了。模仿学习的上限，就是示范数据。

### S03 分数不可导，梯度从哪来
- 画面：公式逐行推导：∇J = Σ r ∇π = Σ π r ∇log π = E[r ∇log π]；下方标注"只要能采样、能打分"。
- 屏幕文字：对数导数技巧：∇E[r] = E[r · ∇log π]
- 旁白：可是答案对不对，是一个判分程序给出的，它不可导。怎么求梯度？关键是对数导数技巧：概率的梯度，等于概率乘以对数概率的梯度。代进去，期望奖励的梯度就变成一个期望：每个回答的对数概率梯度，乘上它的得分。这个期望可以用采样来估计。奖励只作为一个数出现，不需要可导，只要能打分。这就是 {REINFORCE|瑞恩佛斯}。

### S04 基线：同样的期望，小得多的方差
- 画面：左侧两条训练曲线（最好手臂的概率），无基线（红）在 0.2 附近徘徊，有基线（绿）升到 0.99；右侧方差对比 84.7 vs 0.053。
- 屏幕文字：减去基线 b：期望不变，方差 ÷1589
- 旁白：采样估计是无偏的，但方差很大。办法是减去一个基线：减去任何常数，期望都不变，方差却可能差很多。在一个老虎机上，把奖励都加十，不减基线的方差是减基线的一千五百多倍。同样训练三百步，不减基线的几乎原地不动，用这一批的平均奖励作基线，很快就学会了拉最好的那只手臂。

### S05 PPO：价值模型和裁剪
- 画面：两个方框"策略模型""价值模型（和策略一样大）"；右边裁剪函数图：横轴 ρ，A>0 时在 1+ε 处变平。
- 屏幕文字：PPO：critic 当基线 + 裁剪 ρ 到 [1−ε, 1+ε]
- 旁白：上一章的 {PPO|P P O} 也在做同样的事。它训练一个价值模型当基线，再用重要性比 {ρ|rho} 修正"用旧样本更新新策略"的偏差，并把 {ρ|rho} 裁剪在一减 {ε|epsilon} 到一加 {ε|epsilon} 之间，防止一步走太远。问题是价值模型和策略一样大，要多占一份显存、多训一个模型，而且奖励只在回答末尾给一个数，它很难在每个位置都估准。

### S06 GRPO：同一道题的其他回答就是基线
- 画面：一道题 2+8 发出 8 个回答卡片，显示回答 10/0 和奖励 1/0；然后计算均值 0.5、标准差 0.535，卡片下方出现优势 ±0.94，正的绿色向上箭头，负的红色向下箭头。
- 屏幕文字：A_i = (r_i − mean) / std
- 旁白：{GRPO|G R P O} 的想法很直接：把价值模型整个去掉。同一道题采样 G 个回答，用验证器打分，减去组内平均分，再除以标准差，就是每个回答的优势。这是训练第一步里真实的一组：八个回答，四个写对了十，四个写成了零。均值零点五，优势正负零点九四。写对的往上推，忘了进位的往下压。

### S07 GRPO 的三个细节
- 画面：三栏：①一组全对 → A 全为 0（零方差组比例 0.56→0.94）；②k3 公式 x − log x − 1 ≥ 0 的小曲线；③两种聚合示意（按回答平均 vs 所有 token 平均）。
- 屏幕文字：零方差组没有梯度 · k3 KL · token 级平均
- 旁白：三个细节。第一，一组全对或全错，优势全是零，这组没有梯度；模型越学越好，这样的组越来越多，实验里从五成六涨到九成四，所以各家都要按难度筛题。第二，可以加一项对参考模型的 {KL|K L}，用 k3 估计，永远非负；用规则奖励时很多团队干脆去掉它。第三，损失对所有回答的 token 一起平均，而不是每条回答先平均，免得长回答里的 token 被稀释。

### S08 学生超过了老师
- 画面：折线图：进位题贪心准确率 0.11 → 0.91 → 1.00，采样准确率 0.68 → 0.98；一条虚线标"老师 0.684"。
- 屏幕文字：GRPO 60 步：学生超过老师
- 旁白：回到加法实验。用 {GRPO|G R P O} 训练五步，进位题的贪心准确率就从零点一一到了零点九一，十步到了一。采样准确率最后到零点九八，超过了老师。注意，正确答案本来就在学生的分布里，只是不是最可能的那个。强化学习做的，是把偶尔对的做法变成最常见的做法。

### S09 可验证奖励
- 画面：四行表格：数学 → 比答案；代码 → 跑测试；指令遵循 → 逐条检查；工具调用 → 格式 + AST / 执行结果比对。下方一行：MiMo 的环境：可执行测试 · 规则检查 · rubric 判分。
- 屏幕文字：可验证奖励（RLVR）：让程序判对错
- 旁白：强化学习的上限，是奖励的质量。{DeepSeek-R1|DeepSeek R1} 在推理任务上只用规则奖励，理由是神经网络奖励模型在长时间训练里容易被钻空子。数学比答案，代码跑测试，工具调用先查格式，再和标准调用比参数、比执行结果。小米开源的 {MiMo|米莫} 环境，把判分器归成几类：可执行测试、规则检查、按细则逐条判分。

### S10 真实的作弊：去掉标签
- 画面：极小配置演示标注。左边一段带标签的坏 JSON（红色 −1），箭头变成去掉标签的裸 JSON（原来 0 分）；右边：闲聊题空回复 → 1.0。然后出现"守卫 #8：标签外出现 JSON → −1；空回复 → 0"。
- 屏幕文字：奖励只查标签里面 → 模型学会不写标签
- 旁白：接下来是我们自己踩过的坑。写冒烟测试时，最初的奖励只检查工具调用标签里面的内容。极小模型的调用几乎都是坏的，得负一分。{GRPO|G R P O} 跑了不到十步，平均奖励漂亮地上升。一看样本：模型学会了去掉标签，照样输出 {JSON|J son}。没有标签就不算调用，也就没有格式错误，负一变成了零。另外，不需要工具的题，回复为空也能拿满分。修法是第八条守卫：标签外面出现调用样子的 {JSON|J son}，判格式错误；空回复只给零分。

### S11 重演一遍：奖励涨了，本事没涨
- 画面：两张小折线图并排：左"天真奖励"——格式错误率（红）降到 0，正确格式调用（绿）降到 0，真实成功率（黄）0.14→0.02；右"修好的奖励"——正确格式调用升到 1.00，真实成功率 0.14→0.36。
- 屏幕文字：只看格式错误率：两边都"成功"；看真实成功率：一个在退步
- 旁白：我们在玩具上重演了一遍。同一个起点，两种奖励只差这一条守卫。天真的奖励下，格式错误率从零点五九降到零，看起来很成功；可正确格式的调用也降到了零，闲聊题的正常回复从零点五五掉到零点零九，真实成功率从零点一四掉到零点零二。加上守卫，格式问题解决了，真实成功率升到零点三六。策略梯度只会沿着最容易涨分的方向走，它不知道你真正想要什么。

### S12 怎么防：盯住真实指标
- 画面：左边防守清单：严格格式 / 惩罚退化输出 / 留出验证器与人工抽查 / 优先规则奖励 / 每个漏洞一条测试；右边监控表：奖励、格式率、调用率、长度、KL、熵、留出成功率。
- 屏幕文字：别只看平均奖励
- 旁白：一般的防守办法有几条：格式要严，宁可误杀也别留缝；惩罚空回复、超长、伪造工具结果这些退化输出；训练用的奖励和评估用的判据分开，定期抽样本看；能用规则就别用模型打分；每发现一个漏洞，就补一条测试。训练时要同时盯着奖励、格式正确率、调用率、回复长度、{KL|K L}、熵，最重要的是留出集上的真实成功率。

### S13 主线进度与生产级代码
- 画面：极小配置演示标注。表格：tiny GRPO 10 步，奖励 −0.19 → −0.07（噪声大）、格式/调用率 0.50/0.34 → 0.62/0.62；评测 GRPO vs SFT −0.033 [−0.100, +0.000] 持平。下方：zero/post/grpo.py · tool_env.py · configs/main/grpo.toml（G=16，每步 64 题）。
- 屏幕文字：极小配置演示：代码跑通 ≠ 效果
- 旁白：生产级代码在 zero 的 post 目录里，极简版和它逐位对拍。极小配置的冒烟测试跑了十步，奖励从负零点一九到负零点零七，上下跳得很厉害；在冻结的开发集上和 {SFT|S F T} 比，差值的置信区间跨过零，只能算持平。这只说明代码通了。主线模型的真实训练，要等有了 {GPU|G P U}，先和 verl 在同一个小任务上对拍，再开跑。

### S14 小结
- 画面：四个方块连成一行：采样 G 个回答 → 验证器打分 → 组内优势 → 裁剪的策略梯度；底下一行红字"盯住真实成功率"。最后出现"下一章：发布"。
- 屏幕文字：采样 → 打分 → 组内优势 → 更新
- 旁白：总结一下。模仿有天花板；强化学习只需要一个能打分的验证器。{GRPO|G R P O} 每道题采样一组回答，用组内平均分当基线，不需要价值模型。奖励决定了模型会学成什么样，它会钻你没想到的空子，所以要盯住真实的成功率。下一章，我们按预注册的规则做最终评测，把模型量化、发布。

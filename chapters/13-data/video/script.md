## 二、分镜与旁白

### S01 片头
- 画面：章节标题卡"第 13 章 / 数据"，副标题"从一堆网页到一份能训练的数据集"。
- 屏幕文字：第 13 章 · 数据
- 旁白：上一章我们定下了主线模型的尺寸和预算：约七亿参数，四千亿个 token。这一章回答一个更实际的问题：这四千亿个 token 从哪来？网上的文字取之不尽，可大部分是广告、导航栏、乱码和重复的转载。怎么把它们变成一份干净、合法、不偷看考题的数据集，再为它训练一个合身的分词器，就是这一章的内容。

### S02 数据是最大的杠杆
- 画面：两根横条对比预训练 token 数：Qwen3 36T（长）与 MobileLLM-R1 4.2T（短，标 11.7%）；下方一行 Puro-2B 的成本。
- 屏幕文字：同样的尺寸，数据决定上限
- 旁白：先看两个和主线差不多大的模型。Meta 的 {MobileLLM-R1|mobile LLM R1}，九亿五千万参数，预训练只用了四点二万亿 token，是千问三的三十六万亿的百分之十一点七，却在多项推理基准上追平了千问三零点六B。清华的 {Puro-2B|普罗 2B} 只用公开数据，拟合出大约四千四百美元的算力，就能追上千问二一点五B。它们的共同点是：把功夫花在了数据上。

### S03 开放数据集与许可证
- 画面：六张卡片（名称、规模、语言、许可证），许可证有疑问的卡片角上亮黄色"待核实"。
- 屏幕文字：每一份都要核对许可证
- 旁白：好在今天有不少开放的预训练数据集。英文有 {FineWeb-Edu|fine web edu} 和 {DCLM|D C L M}，中文有 {FineWeb-2|fine web 2} 的中文子集和 {Ultra-FineWeb|ultra fine web}，代码有 {Stack-Edu|stack edu}，数学有 {FineMath|fine math}。每一份都要核对许可证：有的要求署名，有的写着仅供研究，有的只给文件编号、内容要另外去取，还有的汇集了许可证各不相同的上游语料。核实不了的，下载器默认拒绝。

### S04 流水线与一份脏网页
- 画面：一排方块"抽取 → 语言识别 → 规则 → 去重 → 模型打分 → 去污染 → 分词分片"；然后下方一根按类型着色的堆叠条，展示脏网页的构成。右上角"极小配置演示"。
- 屏幕文字：便宜的步骤放前面；脏网页 1401 篇
- 旁白：从网页到训练数据，主流做法是一条流水线：抽取正文、识别语言、启发式规则、去重、模型打分、去污染，最后分词、切分片。便宜的步骤放前面，贵的放后面。为了看清每一步在干什么，我们造了一份脏网页：一千零一十五篇莎士比亚和宋词当好文档，再掺进转载、导航页、广告、乱码和打乱词序的假文章，一共一千四百零一篇，每篇都带着标签。

### S05 启发式规则
- 画面：左边列出五条规则；右边每种类型一根"删除率"横条（导航页、广告、乱码满格，乱序很短，好文档 17% 标红）；最后一个莎士比亚片段，人名行高亮。
- 屏幕文字：规则抓格式，抓不住"不像话"
- 旁白：第一关是启发式规则，来自 {Gopher|gopher}、{C4|C 4} 和 {FineWeb|fine web} 三篇论文：词太少不要，停用词太少不要，重复行太多不要，以标点结尾的行太少也不要。导航页、广告、乱码全军覆没。可打乱词序的假文章只删掉了百分之十五，因为它的字符、行长、标点都和真文章一样。反过来，好文档被误杀了百分之十七，大多是莎士比亚：剧本里反复出现的人名行，触发了重复行规则。规则的阈值是在网页上调出来的，要按来源选用。

### S06 去重：Jaccard 相似度
- 画面：一篇文章和它的转载并排，改动的几个字标红；两篇各自切成 5 字符片段，画成两个圆的交集与并集，写出 J = |A∩B| / |A∪B|。
- 屏幕文字：J(A, B) = |A∩B| / |A∪B|
- 旁白：第二关是去重。网上同一篇文章会被转载成千上万次，重复的数据浪费算力，还会让模型死记硬背。精确去重算一个哈希，一样的只留一份；可转载时改了几个字，哈希就完全不同了。我们需要衡量两篇文档有多像：把文档切成五个字符一组的片段，看两个集合的交集占并集多少，这叫 {Jaccard|杰卡德} 相似度。

### S07 MinHash
- 画面：两个小集合的元素按某个随机哈希排成一行，各自最小的元素高亮；换几个哈希函数重复；最后出现公式与 128 位签名条。
- 屏幕文字：P(min h(A) = min h(B)) = J(A, B)
- 旁白：可两两比较几十亿篇文档是不可能的。{MinHash|min hash} 的想法很巧：随便取一个哈希函数，看每个集合里哈希值最小的元素。两个集合并在一起后最小的那个元素，恰好落在交集里的概率，就是 {Jaccard|杰卡德} 相似度，这时两个最小值相等。用一百二十八个哈希函数，得到一个一百二十八位的签名，相等的位数占比，就是相似度的估计。

### S08 LSH 的 S 曲线
- 画面：签名切成 16 段 × 8 行；右边坐标系画 P(s) = 1 − (1 − s⁸)¹⁶ 的曲线，实测点落在曲线上；拐点 0.71 标出；最后一行"多余副本 130 → 71 → 2"。右上角"极小配置演示"。
- 屏幕文字：P(s) = 1 − (1 − s^r)^b
- 旁白：再把签名切成十六段，每段八位。只要有一段完全相同，两篇文档就成为候选。相似度为 s 的一对被抓到的概率，是一减去，一减 s 的八次方，的十六次方。画出来是一条 S 形曲线，拐点在零点七一附近。我们造了六千对已知相似度的集合去测，实测和公式几乎重合。用在脏网页上，多余的副本从一百三十份降到七十一份，再降到两份，没有一对被误合并。

### S09 基于模型的质量过滤
- 画面：上半部分是 FineWeb-Edu 的三步（大模型标 46 万篇 → 训练小分类器 → 给 15T token 打分、留 ≥3 分）；下半部分是玩具版的阈值表，0.5 那一行高亮。
- 屏幕文字：大模型标一小部分，小分类器打全部
- 旁白：第三关是基于模型的质量过滤。{FineWeb-Edu|fine web edu} 让 Llama 3 七百亿参数的模型给四十六万个网页的教育价值打分，再训练一个小分类器给十五万亿 token 全部打分，只留三分以上的，删掉了百分之九十二。我们的玩具版请评审员标二百五十篇，训练一个逻辑回归，最有用的特征是相邻两个词有多眼熟。阈值零点五时，精确率零点九七，召回率零点七；阈值越高，抓得越全，误伤也越多。

### S10 合成改写
- 画面：Kimi K2 的三行对照（柱状图）；旁边两行小字：Nemotron-CC 1.9T 合成、Phi-4 合成 40%。
- 屏幕文字：改写 10 次各看 1 遍 > 原文重复 10 遍
- 旁白：好数据是会用完的。越来越多的模型让大模型把已有文本换个写法重写一遍。{Kimi K2|kimi K 2} 做过一个对照：同一份维基文本，原样重复十遍，{SimpleQA|simple QA} 是二十三点七六；改写十次、每份只看一遍，是二十八点九四。英伟达的 {Nemotron-CC|nemotron CC} 里有一点九万亿 token 是改写出来的，{Phi-4|phi 4} 的合成数据占到百分之四十。但改写可能带来幻觉，用来改写的模型也必须允许拿它的输出训练别的模型。

### S11 配比与代理实验
- 画面：左边一个饼图：主线暂定配比；右边列出 Puro-2B 的代理实验流程（同一个起点 → 续训 8.4B token → 15 项基准的能力向量）。
- 屏幕文字：配比靠对照实验，不靠公式
- 旁白：有了几份干净的数据，还要定配比。没有公式能算出来，大家都靠小规模的对照实验：同样的模型、同样的算力，只换数据。{Puro-2B|普罗 2B} 从同一个千问三零点六B出发，每个候选数据续训八十四亿 token，比十五项基准。主线的暂定配比是：英文网页百分之四十五，中文百分之三十，代码百分之十五，数学百分之十，第二步用代理实验再确定。

### S12 我们的两个消融
- 画面：左边：脏数据 vs 过滤后，英文、中文 bpb 的分组柱状图（两个种子），配对差值标出；右边：三种配比的各领域 bpb。右上角"极小配置演示"。
- 屏幕文字：同样的算力，只换数据
- 旁白：我们自己也做了两个这样的对照。第一个：同样的小模型、同样训练四十万个 token，一个用原样的脏网页，一个用过滤后的数据。过滤后的那个，在干净验证集上英文每字节少了零点零三到零点零四比特，中文少了零点零八。有趣的是，脏数据的训练损失反而更低，因为导航页和重复文章很好猜。另外，换一个随机种子，结果能差零点一，所以只能在同一个种子下配对比较。第二个对照换了三种配比，每种两个种子：代码占一半时，代码的比特每字节从三点七五降到二点五九；英文为主时，中文就吃亏。意外的是，代码为主在中英文上也更好，两个种子都一样。我们没有可靠的解释，这恰好提醒我们：这么小的实验，结论不能直接搬到大模型上。

### S13 去污染
- 画面：一道考题和一篇训练文档，共享的 13 个词高亮；下方 n 的对照表（原样 / 改格式 / 改写 / 其它命中），n=13 一行高亮。右上角"极小配置演示"。
- 屏幕文字：13-gram：抓得住原样，抓不住改写
- 旁白：第四关是去污染。如果考题出现在训练数据里，分数就不可信了。做法是把考题切成十三个词一组的片段，训练文档里只要出现任何一个，就整篇删掉。原样泄漏和改了大小写标点的，十二篇全部抓到；改写过的考题抓不到。把 n 调小到五，又会把常见的搭配当成泄漏。还有三篇意外命中，其实是真泄漏：同一首宋词在语料里本来就出现了两次。

### S14 主线分词器
- 画面：左边坐标系：横轴词表大小（对数），纵轴字节/token（中、英、代码三条线）；右边"FLOPs/字节"与"总参数"两列小表，0.8B 的红线；最后出现主线的选择。再一行：qwen2 与 qwen3.5 正则在印地语上的切分对比。
- 屏幕文字：比的是"读同样多的文字要花多少算力"
- 旁白：最后是分词器。词表越大，同样的文字切出的 token 越少，可嵌入层和输出层也越大。真正要比的，是读完同样多的文字要花多少算力，也就是每个 token 的算力，除以每个 token 覆盖的字节数。我们从主线要用的预训练数据里抽了三十兆的中英文和代码，训练了七种大小的词表：这个数在六万五千五百三十六最低，词表再小或再大都会变贵；而千问的十五万词表放在主线的宽度上，总参数会超过零点八B。所以主线选六万五千五百三十六。预切分正则换成千问三点五的版本：对中英文和代码几乎没有影响，印地语、泰语这类带组合符号的文字，不再被切碎。
